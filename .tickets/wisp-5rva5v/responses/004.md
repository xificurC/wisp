The task states "I don't understand how the ctb.proxy works" and asks for a changes sketch. This text answers how ctb.proxy works and what wisp needs.

ctb.proxy answers non-stream chat-completions JSON and returns HTTP 400 for `stream: true`.
One path is standard: non-stream chat through the proxy. The streaming route is the private Codex endpoint, needing the subscription token in the container.
wisp needs a stream-off switch, a whole-body read, and a message-to-delta adapter.

1. `src/ctb/proxy.py` `complete` and `_text` establish two limits: no streaming branch, and image parts flatten to empty text, so `load_image` results never arrive.

2. `wisp/wisp` `body_of_chat`, `sse_stream`, `TurnAcc` establish the edits: gate `stream`/`stream_options` on `WISP_LLM_STREAM=false`, add a whole-body JSON read beside `Http.post_stream`, add `reply_of_chat` renumbering `tool_calls` by position, emit one `data:` chunk so rendering stays unchanged.

3. `src/ctb/agents/base.py` `CuratedAgent` plus `matrix.py` establish the benchmark side: `src/ctb/agents/wisp.py`, one-script `ARCHIVE`, `proxy=True`, `CTB_PROXY_KEY`, `--context-guard 500k` (percent reads `/v1/model/info`, which 404s), usage from `wisp.usage`.
