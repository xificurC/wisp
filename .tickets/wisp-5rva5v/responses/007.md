## What changed in `wisp/wisp`

- Env switch. `stream_enabled_of` reads `WISP_LLM_STREAM`: unset or empty means a stream; `false`, `0`, `no` and `off` (trimmed, any case) turn the stream off; any other value fails and names the forms.
- Provider gate. `build_request` fails with one line when the switch is false and `WISP_LLM_API` is not `openai-chat`.
- Body gate. `body_of_chat` sends `"stream": false` in the same key position and drops `stream_options`; every other key keeps its place.
- Whole-body read. `Http.post_json` mirrors `post_stream`'s request, error wrapping and `meta` fill, reads one whole body and raises `HttpError("not a JSON response: ...")` on a parse failure.
- Reply adapter. `chat_chunk_of` maps `message.content`, each present `DEFAULT_THINK_FIELDS` key, every tool call with `index` set to the call position, `finish_reason` and `usage`.
- Turn dispatch. `json_turn` logs `http post`, `http_error` and `http_done ... mode=json payloads=1`, and prints one `data:` line, so `wisp.stream`, `render-live` and `render-past` need no change. `turn_stream` chooses `sse_stream` or `json_turn`.
- Docs. `WISP_LLM_STREAM` joins the module docstring env list and the `wisp run` and `wisp continue` help env lines, with the one-sentence explanation.
