The task states "Explain the proxy streaming issue. What does the benchmark repo return that `wisp` doesn't support?" and "why is it incompatible with the benchmark"; it names no reader.

This text explains where the proxy and wisp disagree on the wire.

The proxy refuses every `stream: true` chat request with HTTP 400 and answers only non-stream JSON. It returns one `application/json` `chat.completion` body, never `data:` SSE lines. wisp's three APIs are request shapes; all three stream, and wisp parses only chat-shaped chunks.

1. From `src/ctb/proxy.py` `complete`, the check `if req.get("stream")` raises `UpstreamError(400, "stream is not supported...")`, and `do_POST` serializes that as the reply; the message says "remove :stream from the features" because the proxy was written for samizdat's `:stream` feature flag. The upstream is already streamed: `codex_body` sets `stream: True` and `call_codex` reassembles the events, so the refusal lives in the proxy's translation layer, not in GPT.

2. From wisp `body_of_chat`, `body_of_responses`, and `body_of_anthropic`, each body hardcodes `"stream": True`; `body_of_chat` adds `stream_options.include_usage`. `sse_stream` drops every non-`data:` line and calls `fail` with "model endpoint returned an unexpected response" when no payload arrives, so one JSON body is a dead turn, not a reply. wisp has no non-stream branch.

3. From `do_POST` and `do_GET`, only `/chat/completions` and `/models` route; `/v1/responses` gets 404, so `WISP_LLM_API=openai-responses` cannot reach the proxy. The upstream is `chatgpt.com/backend-api/codex/responses` with `chatgpt-account-id` and a subscription token, so it is not api.openai.com Responses either.
