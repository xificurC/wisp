## TLDR

`bench/install.sh` computed `BENCH_DIR` one directory too high, built the venv at the wisp repo root, and called a nonexistent `<repo>/bin/harbor`. The path fix is in, the debris venv is removed, and a rerun validated the whole installer end-to-end.

## Root cause

`bench/install.sh` line 6 was `BENCH_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`. The `/..` was copied from `bench/bin/harbor`, where it is correct because that shim sits inside `bench/bin/`. `install.sh` sits directly in `bench/`, so `/..` resolved to `/home/pnagyux/code/wisp`. Consequences: the script created `.venv` at the repo root (stray, 41 packages including harbor), and line 10 invoked `/home/pnagyux/code/wisp/bin/harbor`, which does not exist — the reported error.

## Fix and validation

- Line 6 now resolves to `bench/` itself: `BENCH_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"`.
- Removed the stray `/home/pnagyux/code/wisp/.venv` created by the failed run (timestamped 14:27 today, self-contained shebangs, referenced by nothing outside itself).
- Reran `bash bench/install.sh`: built `bench/.venv`, installed harbor 0.24.0, and the final check line printed `0.24.0` through `bench/bin/harbor` — the shim now prefers `bench/.venv` over the curated-terminal-benchmark fallback.
- Re-ran the first-pass dry-run (`--print-config`): the `wisp_harbor:Wisp` agent resolves under the new venv and the job config prints (terminal-bench 2.0, 20 tasks, DeepSeek V4.1 Flash, podman).
- Ticket `wisp-az7xi5` Setup section records the fix.

The first real pass from the ticket's Next list is now unblocked: `bench/bin/harbor run -d terminal-bench@2.0 -a wisp_harbor:Wisp -m MODEL -e podman -l 20 -n 4 -k 1 -y -o bench/jobs/tb2-first`, then `python3 bench/aggregate.py bench/jobs/tb2-first`.
