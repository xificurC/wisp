**Goal of this turn:** make `wispy commit` rewrite the ticket name into a definition of the work, and put that name in the commit subject.

**TLDR:** The seal session now renames the ticket before committing, and `wispy` re-derives and checks the subject from the committed name, so a question like `can wisp render-live stream tool calls?` reaches the log as `wisp render-live: stream tool calls and their results`.

## The problem

The old `commit_turn` froze `commit_subject(ticket)` — `<status>(<id>): <name>` — into the prompt as a literal, and `commit-rules.md` said "Use the subject given above." Tickets get named before the work is clear, so the frozen value carried the request into the commit log. Commit `2850e59` is the example in the request.

## The change

Four files in `/home/pnagyux/code/wisp`:

- `wispy/wispy`
  - `name_problem(name)` holds the mechanical half of the name rule: empty, ends with `?`, leads with an interrogative or auxiliary word (`can`, `should`, `does`, `is`, `how`, `what`, `will`, ...), or runs past `NAME_WORDS = 12`. It returns the reason, or `""`.
  - `ticket_meta(world, ticket)` re-reads the frontmatter after the session, so both the name and the status come from the committed record, not from the values read before the session.
  - `commit_turn` now prints `Ticket name now:` plus the subject form `<status>(<id>): <name>` and no literal subject. The model derives the literal after renaming, so no value is frozen.
  - `cmd_commit` gained two post-commit gates after the existing dirty-record check: a bad name exits 1, and a `git log -1 --format=%s` that differs from `<committed status>(<id>): <committed name>` exits 1. Both notes name the repair: edit the name in `ticket.md`, then `git commit --amend`. The commit stands; the gates do not undo it.
- `wispy/prompts/commit-rules.md`: new `## The name` section, with the two worked examples from the request and the five name lines. `Decide` now says to build the subject from the header values and the written name. The wispy-check bullet lists the two new gates. Steering loses priority over the name rule along with the subject rule.
- `md/design/wispy.md`: the rename paragraph, the name rule, and two new rows in the gates table marked "Exit 1, the commit stands".
- `README.md`: one bullet under the `wispy` added-functionality list.

## Decisions settled

- One session, not two. The seal session already reads the ticket, state, responses, and diff; a separate naming call would duplicate that read.
- `wispy` still writes one ticket field (the status). The session writes the name; the rename travels in the same commit.
- Hard gates, not advisory. A question name or a mismatched subject fails the command. The dead end is accepted because the alternative — a stale subject in history — costs more; the repair is a name edit plus `--amend`.
- The status in the expected subject comes from the committed ticket, so a status changed inside the session also fails loudly instead of committing a stale subject.
