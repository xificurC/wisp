Goal: remove the human gate from the `wispy commit` name check.

TLDR: A name or subject that fails the seal check now gets one repair turn in the same commit session; a second failure stands and `wispy commit` exits 0. No operator amend remains.

**The seal repair turn.** A "seal repair turn" is a second `wisp run -d <session>` on the commit session. The turn carries the ticket, the state, the exact failure, and the order to fix the `name:` line and run `git commit --amend`. The turn makes no new commit.

**Code (`wispy/wispy`).**
- `seal_problem` holds the name rule and the subject check and returns the failure text.
- `cmd_commit` calls `seal_problem` after the existing dirty-record gate. On a failure, `cmd_commit` sends one repair turn, re-reads the seal, and accepts the commit either way: "the seal holds after the repair turn" or "the seal still fails; the commit stands anyway".
- `PromptService.commit_repair_turn` builds the turn: the ticket, the state, `Ticket name now` read from the ticket file, the `<seal-gate>` block, and the rules file.
- The module docstring states the new exit.

**Prompt (`wispy/prompts/commit-rules.md`).**
- New `## The repair turn` section.
- `## Decide` now names "or wispy sent a repair turn" as the amend permission.
- The post-commit check list names the repair turn.
