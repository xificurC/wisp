TLDR: `wisp` now always stores a loaded image, and a vision-off model sends a text placeholder in place of the image parts. Declaring a model non-image repairs a poisoned session in place, because the stored bytes stay and never reach the wire.

## What changed

**`load_image` keeps the image.** The tool-time refusal is gone from `_run_load_image` in `/home/pnagyux/code/wisp/wisp/wisp`. The tool reads the file, stores `attachments`, and exits 0 under every vision setting.

**The wire decides.** One new helper, `text_only_parts`, replaces each image part with the pi placeholder when vision is off:
- `(image omitted: model does not support images)` on a user record.
- `(tool image omitted: model does not support images)` on a tool record.

The helper runs in `message_of` and `chat_image_message` (openai-chat), `items_of_responses`, and `items_of_anthropic`. `body_of_chat`, `body_of_responses`, and `body_of_anthropic` call `vision_enabled_of` once and pass the boolean down. Stored records keep their bytes, so a later run with vision on replays the real image.

**`--attach` keeps its start-time refusal.** Decision (b) settled as keep. The refusal guards new input before any bytes are stored and cannot poison. The wire placeholder covers the stored history, which is the poisoning case.

**Docs.** The `wisp` module docstring, `run` and `continue` help, `vision_enabled_of`, `refresh_model_cfg`, `MODELCFG_BOOL_FIELDS`, and `/home/pnagyux/code/wisp/AI_SETUP_RECIPES.md` now describe the wire placeholder instead of the tool-time refusal.

**Tests.** `/home/pnagyux/code/wisp/wisp/tests/test_vision_gate.py` has 23 tests: vision resolution, image storage under every setting, the placeholder in all three builders, the modelcfg path through `build_request`, and unchanged record bytes. `/home/pnagyux/code/wisp/wisp/tests/test_providers.py` gained `_Fs.exists`, because `build_request` now reads `wisp.modelcfg`.
