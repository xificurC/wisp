**What changed**

- `wispy demote [< reason]` (wispy/wispy): demotes the session named by the open `.phase` (work or distill, never commit) — saves its response, records it in `sessions.txt`, clears `.phase` — then starts a fresh work session with the same skills. The successor's first turn carries a recovery note naming the demoted session and the piped reason. Generic: it escapes any session whose requests keep failing, whatever the cause. `wisp` itself got no recovery command.
- `decide_after_work` maps wisp rc 77 (http error) to the `api` action, not to a distill in the same session; the api and distill-failure notes now name `wispy demote` as the repair.
- wisp: modelcfg entries accept a `vision` boolean; `vision_enabled_of` resolves `WISP_LLM_VISION` env (on/off words, typo fails) → modelcfg `vision` → default on; `_run_load_image` degrades to a text refusal (exit 1, no `attachments`) when vision is off; `wisp run --attach` fails at start under vision off, before the prompt is read.
- `AI_SETUP_RECIPES.md`: `WISP_LLM_VISION` env row, `vision` field documented with the GLM 5.3 example, `vision` added to the litellm (`supports_vision`) and openrouter (`input_modalities`) jq recipes, an opencode-go by-hand note, and a check-one-model vision query.
