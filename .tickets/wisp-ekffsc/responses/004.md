**Goal of this turn:** scout whether an API can report model capabilities, before deciding between strip-retry and error sniffing.

**TLDR:** Yes, the company LiteLLM server exposes a capabilities API: `GET /model/info` answers a `supports_vision` boolean per model. But GLM 5.3, the model that poisoned sessions in this ticket, reports `null`, so the API alone does not fix the original case.

**What the probes found:**

- The company LiteTTM server answers `GET /model/info` with the same bearer key wisp already uses. Each deployment entry carries `model_info.supports_vision`. Live count: 34 entries, 25 `true`, 4 `false`, 5 `null`.
- GLM 5.3's entry says `supports_vision: null`. Its backend is a custom `hosted_vllm` deployment; LiteLLM leaves vision undeclared for those unless a server admin declares it. The 4 `false` entries (laguna-s-2.1, minimax-m2.5, Qwen 3.8 Flash Next, Qwen 3.8 27B) prove the declaration pipeline exists and is editable server-side. The field is an admin declaration, not measured truth.
- The standard `GET /v1/models` on the same server carries only ids and token limits, no capability fields.
- Other providers: OpenRouter's public `GET /api/v1/models` returns `architecture.input_modalities` per model (e.g. `Qwen 3 32B` is text-only). OpenAI and Anthropic model-list endpoints return no capability fields at all.

**How this reshapes the decision:**

- Your masking concern about strip-retry is valid: a 400 caused by a wrong image format, on a model that does take images, would be mislearned as vision-off. The capabilities query separates "no images" from "bad format" for every declared model.
- The clean options now stack: (1) a server-side declaration of GLM 5.3 fixes the original poison case with zero wisp code; (2) wisp could query `/model/info` at run start and feed the answer into `vision_enabled_of` as a resolution step (env > modelcfg > server answer > default on), trusting true/false, letting null fall through; (3) strip-retry, or the modelcfg file, stays the backstop only for undeclared models like GLM 5.3 is today.
- No error-text sniffing is needed for any model the server declares.
