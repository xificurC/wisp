## The mechanism: strip-retry

Name: **strip-retry** — on a 400, rebuild the request without image parts and resend it once, in the same round.

Today's chain, confirmed again in the code: `Llm.turn` (wisp/wisp, line 4021) builds the body and calls `turn_stream`; the 400 raises `HttpError`, nothing between `Llm.turn` and `main` (line 5968) catches it, the run exits 77. The new hook sits in `Llm.turn`:

1. `turn_stream` raises `HttpError` with status 400, and the conversation holds records with `attachments`, and vision is not learned off yet. Then wisp sets a world flag `vision_learned_off`, rebuilds the request, and retries once inside the same turn.
2. A second failure re-raises the original error, so `main` exits 77 exactly as today. `wispy`'s api mapping and `wispy demote` stay as backstops for every other cause.
3. No error-text sniffing. The retry is the test: if the request passes without image parts, the images caused the 400. Your live poison drill's body ("GLM 5.3 W4A8 is not a multimodal model") is one wording among many providers; matching strings is brittle and the retry needs no string.

## Why it composes with the existing gate

`vision_enabled_of` (line 3844) gains one resolution step: the `vision_learned_off` world flag returns False. Everything already built reads that function:

- `_run_load_image` (line 3659) degrades every later `load_image` in the same run to the existing text refusal: inspect the file with bash or python3 instead. That is your requested behavior, with no new tool code.
- The `--attach` start check (line 1170) refuses attachments after learning, same wording.
- The three body builders (`body_of_chat` line 4494, `body_of_responses`, the anthropic builder) start consulting `vision_enabled_of`: vision off skips all `pending_images` collection, so stored attachments never reach the wire again.

## Honesty toward the agent

The stored tool record says "Loaded image: foo.png". A silent strip would let the model believe it saw the image. So the builder, when vision is off and a tool record carries attachments, appends one suffix line to that tool message's wire text: the endpoint of this run takes no image content, the image was not delivered. This is wire-only surgery, the same pattern as the steer tag in `user_text_of`. The stored record in wisp.jsonl keeps its bytes and its original text; the transcript stays truthful. One `wisp.log` line (`vision_off_learned round=N status=400`) makes the rescue visible.

## Cost, and why no persistence

An unconfigured text-only model pays one 400 per run, at the learning round; every later request in that run is clean, and `wisp continue` on a poisoned session escapes on its first round. I deliberately skip persisting the learned fact across runs: `refresh_model_cfg` (line 3528) overwrites the session's `wisp.modelcfg` from `WISP_LLM_MODEL_INFO_FILE` every run, so that file is not a durable target, and growing `wisp.run.json`'s contract would cost more than one wasted request. Config stays the durable fix — per your state note, adding `"vision": false` to the GLM 5.3 entry in your model-info file turns the gate on today, zero code.
