**Goal.** Model what pi does when a model declares image input but the deployment rejects images with HTTP 400.

**TLDR.** pi has no second opinion on the declaration, so the image reaches the wire, the 400 lands once, and every later request in that session repeats the 400. pi never retries a 400 and never downgrades images, so recovery is entirely user-driven: switch to a text-only declared model, fix the declaration, or leave the poisoned branch with `/tree` or `/fork`.

## Setup

The declaration says image. `models.json` carries `input: ["text","image"]` for a custom entry, and a `modelOverrides` entry can change a built-in model the same way. pi keeps no capability probe and no learned image flag.

## The 400 trace

1. `read` returns a text note plus the image block. The tool consults `ctx.model.input` only to set a UI-only detail, and a declaring model gets no hint.
2. The tool result enters the context before the next request. The image is now in history, committed, with no verdict about delivery.
3. `transformMessages` calls `downgradeUnsupportedImages`. That function returns the transcript untouched when `model.input.includes("image")`. The builders then emit real image parts. The openai-completions builder moves tool-result images into a user message as `image_url` data URLs. The anthropic builder puts them inside the `tool_result` block.
4. The provider answers 400. `retryProviderRequest` retries 408, 409, 429 and 5xx only, so no transport retry happens. The builder converts the error into an assistant message with `stopReason: "error"` and `"400: <server body>"` as `errorMessage`. Auto-retry classifies errors by message text, and the 400 text matches no retryable pattern, so no backoff attempt happens either.
5. The agent loop ends the run on the error message. The session appends the error message. The image stays in its tool result.
6. The TUI prints `Error: 400: ...`. Because the error is non-retryable, the TUI suggests `/bug`. Headless `pi -p` exits 1. `--mode json` leaves the exit code at 0.
7. The next prompt rebuilds the same request body and gets the same 400. Error assistant messages are skipped at the wire, so the image is the only poison. The session stays stuck while the declaration stays wrong.

## Escapes

All escapes are user-driven, and all keep the image bytes in history.

- `/model` to a model that declares text-only. The next request replaces each image part with "(tool image omitted: model does not support images)" and succeeds. This is pi's shipped design.
- Fix `input` in `models.json` or in `modelOverrides`, then re-select the model. A session replacement re-reads `models.json`. `/reload` does not.
- `/tree` to an entry before the read, or `/fork` from an earlier user message. The image leaves the projected context and stays on disk on the abandoned branch.
- `/new` loses the context.

## What does not escape

Compaction does not escape, and `/compact` usually refuses. The cut point keeps about 20k recent tokens, so a short session has nothing to summarize. Threshold compaction cannot trigger either, because the failed turns add almost no tokens. In a long session threshold compaction can drop an older image, and the summary request is text-only by construction. Compaction therefore neither 400s nor reliably heals.

## pi has one 400 downgrade, not for images

The Anthropic builder catches a pre-stream 400 for strict-tool limits, matched by error text, and retries once with strict tools disabled. That path marks the session in an in-memory keyed set that clears at session end. No image equivalent exists. The shape is pi's own precedent for the strip-retry design recorded in the ticket.

## Two silent variants

- **Declares image, ignores image, answers 200.** No error and no local hint. The model answers from text alone and may fabricate. Only a model switch or a declaration fix changes behavior.
- **Declares text, takes images.** pi sends the placeholder and the TUI prints "[<model> does not support images; it saw a placeholder instead]". A declaration fix plus a re-selected model replays the stored bytes.

A third variant is placement, not capability. Anthropic accepts images inside a `tool_result`. A proxy that accepts user images but rejects tool-result images returns 400 on every successful read. The escapes are a model switch or an `api` change to openai-completions, which moves tool images into a user message.

## Consequence for the wisp port

The pi shape does not cover the misconfigured model. With the wire placeholder a misdeclared model still receives the image and still returns 400. The placeholder rescues only under-declared models.

Port decision (a) is therefore unchanged by this scenario. The wire placeholder adds exactly one recovery that the shipped wisp tool-time gate destroys: the stored bytes stay replayable under a modelcfg fix or a model switch. The misdeclared case keeps wisp's rc 77 to wispy `api` to `wispy demote` backstop. That backstop is stronger than pi's manual `/model` and `/tree`, because one command replaces the poisoned session.
