## The shape after your answers

The single biggest consequence is that **most of §5.3 disappears**. Rev 1's claim/lease/heartbeat/gc existed because two pools could claim one task. With one `wispies` process, the dispatch is a rename by the only writer, and a session is a child process with a wall clock — so liveness is `waitpid`, not `wisp.jsonl` mtime. Answers to your four sub-questions are in §6:

- **Heartbeat**: no. The reader that needed the mtime was a second process that did not own the run.
- **Reclaim**: no. A task is never owned twice. Dead work comes back as *new tasks* from the salvage session.
- **Split/finish/status/events**: split validation survives, because it guards cost, not a race. Finish, status, and events go — the actuator is the only reader and the only writer. The only atomic rule left is the agent's enqueue: dot-prefixed temp file plus rename inside `inbox/`.
- **Events**: there is no event stream. `meta.json` per task, `ledger/runs.jsonl` per session, the wisp session dir per transcript.

You asked whether 5.1 and 5.2 hold up. 5.1 halves: `claim/`, `slots/`, `ledger/reserved/`, `events.jsonl`, `children`, `verdict.md`, `config.toml` are gone. 5.2 loses `status`, `blocked-on`, and the rights block, and gains `binds`/`emits`/`writes`.

## Waiting and evolution without worktrees

Waiting is a board state, not an agent state: a chem is `chems/<name>.want` (a monotonic producer list) plus `chems/<name>/<task-id>`. A decomposition makes the actuator copy the parent's `emits` onto the successors and register them as producers, so the binder still waits for the whole contribution. A locked board (nothing ready, nothing running, an incomplete chem whose producers are all terminal) starts one capped `unblock` session.

Diversity without worktrees, in cost order: **parameter grid** (candidates are values, not files), **flag-gated strategies** (one new file per candidate, discovery by directory convention, no shared registry to conflict on), **serialized attempts** in one scope with snapshot/restore. Conflict between concurrent writers is handled by a `writes:` path-prefix table that blocks dispatch on overlap.

## Verified, not assumed

I tested nono v0.80.0 on this host (§3.4.1). Landlock V6 is enforced: an unlisted path is denied for read *and* write. Three facts that change the design:

1. Non-interactive mode refuses to start without `--allow-cwd`.
2. The default profile grants **write on `/tmp`** — so the board cannot live there.
3. A grant on a non-existent path silently does nothing, so `writes:` entries must exist or be created by the actuator.

Also: `wisp new --parent` loses links under concurrency (last-writer-wins), so the board must not depend on wisp's `children` list.
