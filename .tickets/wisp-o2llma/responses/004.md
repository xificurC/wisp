## Why `WISP_LLM_ANTHROPIC_VERSION` existed

`git log -S` finds the variable only in the initial import (f8a3040). wisp sent `x-api-key` for the anthropic shape, hardcoded, and had no way to set a second header. Anthropic requires `anthropic-version` on every request, so the variable was the only escape hatch. No doc, note, or help line names the variable, so a native Anthropic run fails unless the user guesses it. The variable is now redundant: `WISP_LLM_HEADERS` carries any header.

## What the validated sources say

Codex backend, from `openai/codex` at `main`:

- `codex-rs/codex-api/src/requests/headers.rs` sends `session-id` and `thread-id`. Both names use hyphens.
- `codex-rs/login/src/auth/default_client.rs` sets `originator` and `User-Agent` on every request. The default originator is `codex_cli_rs`.
- `codex-rs/model-provider/src/bearer_auth_provider.rs` adds `Authorization: Bearer` and `chatgpt-account-id`.
- `codex-rs/core/src/client.rs` always sends `include: ["reasoning.encrypted_content"]`. `codex-rs/protocol/src/config_types.rs` defaults the reasoning summary to `Auto`.
- litellm mirrors the route and sends `session_id` with an underscore. Apache and nginx drop underscore headers by default, so wisp follows codex and uses the hyphen. `openai-python` carries no Codex backend route.

Anthropic, from the vendor docs and SDK:

- `platform.claude.com/docs/en/manage-claude/authentication` shows `Authorization: Bearer YOUR_API_KEY` and calls `x-api-key` the legacy alternative.
- `platform.claude.com/docs/en/api/versioning` states every request must send `anthropic-version`, example `2026-10-21`.
- `anthropic-sdk-python` at `main` sends Bearer for an API key and always sets `anthropic-version`.
- litellm still sends `x-api-key` to `api.anthropic.com`, and switches to Bearer plus `anthropic-beta: oauth-2025-04-20` for an `sk-ant-oat` token.

The Bearer result removes the earlier snag: the subscription row no longer needs a duplicated token or a deleted `x-api-key`.
