**Goal.** Decide whether wisp's environment knobs can run OpenAI and Anthropic API keys and subscription tokens today, and what wisp needs for a provider-independent auth flow.

**One-sentence summary.** OpenAI API keys work with a base-URL trap, Anthropic API keys fail without an undocumented version header, OpenAI subscription tokens are blocked by the fixed `/v1` path, and Anthropic subscription tokens work only through a duplicated-header workaround.

**Four-sentence summary.** Wisp composes every endpoint as `WISP_LLM_URL` plus a hard-coded `/v1/...` path, so the URL knob cannot express the Codex route or a vendor base that already ends in `/v1`. Wisp's auth is hard-coded per shape, and the required Anthropic version header has no default. `WISP_LLM_HEADERS` is a real escape hatch, but the overlay cannot delete a default header or reference the key. A four-fact model (endpoint, shape, credential, headers) covers every current and future OpenAI- and Anthropic-compatible endpoint with no provider presets.

## What wisp does today

| Fact | Knob | Current behavior |
|---|---|---|
| Endpoint | `WISP_LLM_URL` | Base URL. Wisp appends a fixed path: `/v1/chat/completions`, `/v1/responses`, or `/v1/messages`. |
| Shape | `WISP_LLM_API` | `openai-chat` (default), `openai-responses`, `anthropic`. |
| Credential | `WISP_LLM_API_KEY` | Required. Bearer for the two OpenAI shapes; `x-api-key` for `anthropic`. |
| Extra headers | `WISP_LLM_HEADERS` | One JSON object, merged last. `{session}` substitutes. |

The endpoint join is `url.rstrip("/") + path`. No path override exists. A base ending in `/v1` yields `/v1/v1/...`.

## The missing features

1. **No path override.** Wisp owns the `/v1/...` suffix. A provider route outside that convention is unreachable.
2. **No URL normalization.** A base ending in `/v1` doubles the segment.
3. **No auth mode.** Wisp cannot send Bearer without `x-api-key`, or send no auth at all.
4. **No default `anthropic-version`.** Native Anthropic requires the header on every request.
5. **Incomplete header overlay.** A JSON `null` becomes the literal string `None`; the key cannot be referenced; a default header cannot be deleted.
6. **Wrong docs.** README lists `WISP_LLM_API=(anthropic | chat | responses)`; wisp accepts only `openai-chat`, `openai-responses`, `anthropic`. The `run` and `continue` help omits `WISP_LLM_API` and `WISP_LLM_ANTHROPIC_VERSION`.

One adjacent wart: `/v1/model/info` returns 404 on OpenAI and Anthropic. Wisp warns on stderr every run, leaves `wisp.modelcfg` empty, and a percent context guard then fails at start. Token guards still work.

## The coherent solution: four independent facts

Do not add provider presets. Presets rot when a vendor changes a path or a header. Complete the four primitives instead.

**1. Endpoint.** Keep `WISP_LLM_URL` as a base. Add `WISP_LLM_PATH` for the exact request path. When `WISP_LLM_PATH` is unset, use the shape default and collapse a duplicate `/v1`:

```
base ends with /v1 and default path starts with /v1/  ->  drop the base /v1
```

**2. Shape.** Keep `WISP_LLM_API` as is.

**3. Credential.** Add `WISP_LLM_AUTH=bearer|x-api-key|none`. The default follows the shape, so existing runs keep today's wire. Add a default `anthropic-version: 2023-06-01` for the `anthropic` shape; `WISP_LLM_ANTHROPIC_VERSION` overrides. Make `WISP_LLM_API_KEY` optional when auth is `none`.

**4. Headers.** Keep `WISP_LLM_HEADERS`. Make names match case-insensitively, make `null` delete a default header, and add `{key}` beside `{session}`. The key then appears once, in `WISP_LLM_API_KEY`.

`WISP_LLM_AUTH` is a convenience, not the only path. With `null` deletion and `{key}`, every scheme is expressible through headers alone. The named mode makes intent clear and guards the no-key case.

## After the change: the hard cases

``` shell
# OpenAI API key; both bases work
export WISP_LLM_URL=https://api.openai.com/v1
export WISP_LLM_API_KEY=sk-...
export WISP_LLM_API=openai-chat

# Anthropic API key; no version export needed
export WISP_LLM_URL=https://api.anthropic.com
export WISP_LLM_API=anthropic
export WISP_LLM_API_KEY=sk-ant-...

# Anthropic subscription token; no x-api-key sent
export WISP_LLM_AUTH=bearer
export WISP_LLM_API_KEY=sk-ant-oat01-...
export WISP_LLM_HEADERS='{"anthropic-beta":"oauth-2025-04-20"}'

# OpenAI subscription token
export WISP_LLM_URL=https://chatgpt.com/backend-api/codex
export WISP_LLM_PATH=/responses
export WISP_LLM_API=openai-responses
export WISP_LLM_API_KEY=<access token>
export WISP_LLM_HEADERS='{"ChatGPT-Account-Id":"<account id>"}'

# Azure OpenAI
export WISP_LLM_URL=https://my-resource.openai.azure.com
export WISP_LLM_PATH='/openai/deployments/gpt-4/chat/completions?api-version=2024-10-21'
export WISP_LLM_AUTH=none
export WISP_LLM_HEADERS='{"api-key":"{key}"}'

# Local model
export WISP_LLM_URL=http://localhost:11434
export WISP_LLM_AUTH=none
```

The OpenAI subscription body is close, not proven. Wisp sends `store:false` and standard Responses items. Wisp does not send `include: ["reasoning.encrypted_content"]`, so multi-turn reasoning replay would degrade.

## Compatibility, scope, and boundaries

- Every working configuration keeps working. The only wire change is the Anthropic version header, which Anthropic requires.
- The `null` behavior changes from `"None"` to deletion. No working configuration relies on the string `"None"`.
- Scope: about 60 lines in `wisp/wisp`, six unit tests in `wisp/tests/test_providers.py`, and updates to `README.md`, `md/notes/providers.md`, and the `run`/`continue` help.
- Quieting the 404 model-info warning is a separate five-line fix. It is not part of the auth change.
- Wisp consumes a subscription token; wisp does not obtain or refresh one. Token acquisition and refresh stay outside wisp. Using a subscription token outside the vendor's client may breach the vendor's terms.
- I had no OpenAI or Anthropic key in this environment. The OpenAI and Anthropic API-key rows rest on live requests with bogus keys, code inspection, and vendor docs. A real end-to-end turn stays unverified until a key is available.
