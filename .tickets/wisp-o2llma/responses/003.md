**Goal.** Settle the two auth primitives you chose — one full-path URL, headers as the only auth override — and explain what the missing `include` field does to reasoning replay and to the prompt cache.

**One-sentence summary.** `WISP_LLM_URL` becomes the full request URL, `WISP_LLM_HEADERS` becomes the only auth override, and one missing request field — `include: ["reasoning.encrypted_content"]` — costs the Responses shape its cross-turn reasoning without breaking the text cache.

**Four-sentence summary.** A full-path URL retires `path_of`, moves endpoint knowledge to the caller, and makes the Codex, Azure, Gemini, and LiteLLM routes reachable. The header overlay gains case-insensitive names, `null` deletion, and `{key}`, and the key check moves from the variable to the resolved header table, which separates "no auth wanted" from "key missing". The export list below covers twelve backends, each route checked live today. The reasoning section shows that `store:false` needs the `include` field for replay, that the prefix cache still hits without the field, and that the real loss is output-priced re-derivation on every tool round.

# 1. One URL

`WISP_LLM_URL` holds the complete request URL: scheme, host, path, and query. wisp sends the request to that string and appends nothing.

| Case | Today | After |
|---|---|---|
| OpenAI API key | base `https://api.openai.com` + hard-coded path; vendor base `.../v1` doubles the segment | `https://api.openai.com/v1/chat/completions` |
| OpenAI subscription | `.../codex/v1/responses` → 404 | `https://chatgpt.com/backend-api/codex/responses` |
| Gemini OpenAI-compat | unreachable; the path has no `/v1` | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` |
| Azure OpenAI | unreachable; deployment path and query | `https://<res>.openai.azure.com/openai/deployments/<dep>/chat/completions?api-version=2024-10-21` |
| LiteLLM custom prefix | only a guessed base works | the exact proxy URL |

Code changes: `path_of` retires, `rstrip("/")` retires, and the request goes to the URL verbatim. `WISP_LLM_API` keeps one job: it selects the body, tool-spec, and stream grammar. The `run` and `continue` help must call `WISP_LLM_API` the request shape, not the API path.

Start validation: accept only `http` and `https`, and require a non-empty path. A bare origin fails with `WISP_LLM_URL has no path; give the full request URL`. A typo then fails at start, not as a 404 from a composed string the caller never wrote.

Costs, named:

- Every stored config changes once. `wisp.run.json` holds no URL, so a resumed session picks up the new env and its body stays byte-stable.
- Four shell tests (`tests/test_wisp_*.sh`) and the two `README.md` lines change.
- `refresh_model_cfg` loses its route. A full URL cannot derive a sibling `/v1/model/info`. My recommendation: `WISP_LLM_MODEL_URL`, a full URL to the model-info endpoint; unset means no fetch and no warning. That subsumes the separate 404-quieting fix and removes the warning from OpenAI, Anthropic, and OpenCode Go runs.
- `wisp.log` now prints the caller's full URL, query included. Redact query values whose name holds `key`, `token`, or `secret`, and keep the rest for Azure's `api-version`.

# 2. Headers only

Yes. Drop `WISP_LLM_AUTH` and drop `WISP_LLM_PATH`. "Headers only" means no named auth mode, not "no defaults". The defaults stay, so every working configuration keeps its wire.

The rule is four steps:

1. wisp builds three headers: `Content-Type`, `User-Agent: wisp`, and one auth header from the shape — `Authorization: Bearer {key}` for both OpenAI shapes, `x-api-key: {key}` plus `anthropic-version: 2023-06-01` for `anthropic`.
2. `WISP_LLM_HEADERS` merges last. Names match case-insensitively, so `authorization` replaces `Authorization` instead of sending a second header.
3. A JSON `null` deletes a header. `{key}` and `{session}` substitute in a value.
4. After the merge, a surviving `{key}` with an empty `WISP_LLM_API_KEY` fails at start and names the header.

Step 4 is the answer to your second downside. The check reads the resolved table, not the key variable. No key and no `{key}` → no failure. No key and a surviving `{key}` → one precise message. "Local endpoint" and "bad config" stop sharing a sentence.

Step 3 is the answer to your first downside for the odd cases. The common case types nothing:

| Case | `WISP_LLM_HEADERS` |
|---|---|
| OpenAI API key | unset |
| Anthropic API key | unset; the version default covers it |
| Anthropic subscription token | `{"Authorization":"Bearer {key}","x-api-key":null,"anthropic-beta":"oauth-2025-04-20"}` |
| Azure | `{"api-key":"{key}","Authorization":null}` |
| Local, no auth | `{"Authorization":null}` |

Two details to settle:

- `null` currently becomes the string `None`. That dies. No working config uses the string `None`.
- `WISP_LLM_ANTHROPIC_VERSION` appears in no doc. Keep it as a deprecated default-only override for one release, and let the overlay set the header for everyone else.

One more menu item: the key check currently lives in `load_events`. Move the check to `auth_headers_of`, so the model-info fetch and the request use one table.

# 4. What the missing `include` field does

The quoted sentence is about the ChatGPT subscription route, not OpenCode Go. Go speaks chat-completions only. The field matters for `openai-responses` against `api.openai.com` and the Codex backend.

**The mechanism.** `store:false` tells the server to keep no response object. A reasoning model still emits `reasoning` items. With no stored copy, the only carrier of that reasoning is the item's encrypted blob. The server returns the blob only when the request's top-level `include` names `reasoning.encrypted_content`. Opencode's client asks for exactly that: `store:false`, `reasoningSummary:"auto"`, and `include:["reasoning.encrypted_content"]` for gpt-5-class models. The evidence is a string in `~/.opencode/bin/opencode`.

**What wisp does today.** wisp built both halves of the loop except the request field. The stream accumulator stores `delta.encrypted_content` (`wisp/wisp:3140`), and the item builder replays it (`wisp/wisp:3405`). The request never asks, so the field is always absent. Every replayed reasoning item is `{"type":"reasoning","summary":[]}`.

**Why that hurts.** A wisp segment is a tool loop, often many rounds. Each round drops the plan. The model re-derives the plan, can repeat a failed approach, and can contradict an earlier decision. That is a correctness risk first.

**What the cache does and does not lose.** Prompt caching is a prefix cache over request tokens. wisp's item list is byte-stable and its key order is stable. The empty reasoning item is stable too, so the shared prefix keeps matching and the text cache still hits — subject to the endpoint's usual minimum length and idle window. The missing field does not shift a prefix byte.

The real loss sits one layer up. Prior reasoning never enters the input, so the model regenerates that reasoning as output tokens on every round. Output tokens are never cacheable, and output costs several times fresh input. With the field, earlier reasoning becomes input on later turns: cached-read tokens at roughly a tenth of fresh input, and a model that starts from its own prior plan. You still pay the first generation at output rates. You stop paying it again on every round.

**The fix, one field wide.**

- Add `"include": ["reasoning.encrypted_content"]` to the responses body for every `openai-responses` run.
- Set `reasoning.summary: "auto"` when thinking is set, as opencode does. Without it, gpt-5-class models return no readable reasoning text, so `render-past` shows nothing even though the blob replays.
- Replay the stored summary text instead of `summary: []`. The documented contract is to pass the item back as it arrived. Choose this once, because it changes request bytes.

**What stays unproven.** The Codex backend may also demand `session-id`, `originator`, and a non-default User-Agent; the body may reject `tools` in the standard shape. The full-path URL makes the route reachable. A 200 needs a subscription access token, and wisp does not obtain one.

# Open decisions

1. `WISP_LLM_MODEL_URL` — my recommendation, versus dropping the model-info fetch or guessing a sibling route.
2. `WISP_LLM_ANTHROPIC_VERSION` — keep as deprecated override, or remove in the same change.
3. `prompt_cache_key` — a routing hint for the OpenAI shapes. Not now: `x-opencode-session` keys Go, `session-id` keys Codex, and the plain OpenAI API caches without it.
4. Query redaction in `wisp.log` — my recommendation, three lines.
