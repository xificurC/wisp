## Classic answer

### Code changes in `wisp/wisp`

- `WISP_LLM_URL` is the full request URL. `request_url_of` returns the value as written and checks the scheme and a non-empty path. `path_of` is deleted. `sse_stream` and `json_turn` use the full URL.
- `auth_headers_of` sends `Content-Type`, `User-Agent: wisp`, and `Authorization: Bearer {key}` for all three shapes. `WISP_LLM_ANTHROPIC_VERSION` and every `x-api-key` default are gone.
- `WISP_LLM_HEADERS` matches names case-insensitively, a JSON `null` deletes a header, and `{session}` plus `{key}` substitute after the merge.
- `check_request_of` runs at run start in `load_session_state`. A run fails on a missing key only when a surviving header holds `{key}`. `load_events` checks nothing.
- `WISP_LLM_MODEL_INFO_FILE` is read at run start and copied into `wisp.modelcfg`. A missing, broken, empty, or non-numeric file warns and writes nothing, so a hand-written `wisp.modelcfg` survives. Unset means no copy and no warning.
- `openai-chat` and `openai-responses` bodies carry `prompt_cache_key`, set to the session dir's base name. The field lands only when the base name is non-empty.
- Every `openai-responses` body carries `include: ["reasoning.encrypted_content"]`. `reasoning.summary` is `auto` when thinking is set, and a reasoning item replays its `summary_text` beside the blob.
- `safe_log` redacts a query value whose name holds key, token, or secret. The bad-JSON `WISP_LLM_HEADERS` message reports the parse position only.
