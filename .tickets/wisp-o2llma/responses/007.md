**Goal:** answer what `-t` does on the `anthropic` shape, and whether wisp also sends the level.

**In one sentence:** wisp turns thinking on and throws the level word away; depth comes from `WISP_LLM_THINKING_BUDGET`, not from `-t`.

**In four sentences:** `body_of_anthropic` tests `-t` for truthiness only, so `low`, `high`, and `off` build the same body. That body carries `thinking: {"type": "enabled", "budget_tokens": N}`, and no level field. Your premise is right: the Messages API does carry levels, in `output_config.effort`, and wisp does not send that field. So the doc sentence is true but under-specified, and a real bug sits beside it.

**The classic answer:**

The code is `wisp/wisp` lines 3773-3778:

```python
thinking = world.get("thinking")
if thinking:
    budget = max(int(world.get("env").get(
        "WISP_LLM_THINKING_BUDGET", DEFAULT_THINKING_BUDGET)),
        ANTHROPIC_MIN_BUDGET)
    body["thinking"] = {"type": "enabled", "budget_tokens": budget}
```

`world.get("thinking")` is a plain truth test. The string never lands in the body. `-t low` and `-t high` produce byte-identical requests, and so does `-t off`. Depth is one env var, `WISP_LLM_THINKING_BUDGET` (8192, floored at 1024). The level word does survive in `wisp.run.json` and in the `effort=%s` log line, so the disk records a level the wire never sees.

Why did wisp flatten it? The `anthropic` shape was built around the budget, which was the vendor's only depth knob when the shape landed. The OpenAI shapes later gained plain pass-through of the level as `reasoning_effort`. Nobody revisited the anthropic shape after that.

Your premise checks out against the vendor page, `platform.claude.com/docs/en/api/messages`, read today:

- `output_config.effort` takes `low`, `medium`, `high`, `xhigh`, `max`.
- `thinking.type` also takes `adaptive` ("Claude decides when and how much to think") and `disabled`.
- `thinking.budget_tokens` "Must be ≥1024 and less than `max_tokens`".

That last line is a live bug. wisp's defaults are budget 8192 and `max_tokens` 4096. wisp floors the budget and caps nothing, so a plain `-t` run on this shape sends a body the vendor rule forbids. Expect a 400. I did not confirm the 400, because no Anthropic key exists on this machine and a bogus key returns 401 before body validation.

The mapping is a decision, and it changes both the code and the doc sentence. I recorded the finding and the three options in `## Anthropic thinking levels, found 2026-11-06` and left the code alone.

- **A. Level plus budget.** `output_config.effort` carries `-t`; `thinking: enabled` stays with a budget clamped below `max_tokens`.
- **B. Level plus adaptive.** `output_config.effort` carries `-t`; `thinking: {"type": "adaptive"}` needs no budget, so the cap conflict dies and `WISP_LLM_THINKING_BUDGET` retires.
- **C. On-switch alone.** Code stays; the doc says the level word is dropped; the budget clamps below `max_tokens`.

I recommend B. One word reaches one field, the same way `-t` reaches `reasoning_effort` on the OpenAI shapes. B also makes `-t off` fail loudly at the endpoint instead of silently enabling thinking. Pick B, or pick A if you want to keep manual budgets for models that refuse `adaptive`.
