## Goal

Land option C from `.tickets/wisp-gkk6yp/ticket.md`: a `--close` flag on `wispy commit` that closes the ticket before the commit prompt is built, so the commit subject and the committed ticket agree.

## One-sentence summary

`wispy commit --close` now writes `status: 'closed'` into the ticket before the prompt is built, so the subject reads `closed(<id>): <name>` and the six new tests bring the suite to 97 passing.

## Four-sentence summary

The flag is a boolean on the commit command and other commands refuse the flag with exit 2. `mark_closed` runs after the phase and repo gates and before the work-tree check, so the status change itself becomes record that the commit session stages. The flag turns an already closed ticket into a no-op with an "already closed" note. The script docstring, the design doc, and the ticket record now describe the flag, and the ticket frontmatter says `closed`.

## What landed

**Flag parsing** (`wispy/wispy`)
- `Opts.close` holds the boolean; a new `FLAGS` table maps `--close` to the field.
- `parse_args` rejects `--close` on any command but `commit`, with exit 2 and the message `response takes no --close; close the ticket in a commit`.

**The close** (`wispy/wispy:cmd_commit`)
- `mark_closed` sits beside `mark_wip` and calls `set_status(world, ticket, "closed")`.
- `cmd_commit` calls `mark_closed` after `read_steering` and before the `git status` record check.
- Order matters: the ticket `status` write lands before the work-tree check, so a `--close` commit on an otherwise clean tree still finds record and starts the session.
- The prompt header reads `Ticket status: closed`, the subject line reads `closed(ai-test): Test ticket`, and the ticket body inside the prompt reads `status: 'closed'`.
- An already closed ticket gets the note `ticket <id>: already closed` and no rewrite.

**Tests** (`wispy/tests/test_wispy.py`, 91 → 97)
- `test_close_closes_the_ticket_before_the_prompt` checks the subject, the header, the prompt ticket body, and the file.
- `test_close_works_from_an_open_ticket` checks `open` → `closed`.
- `test_close_on_a_closed_ticket_is_noted` checks the no-op path.
- `test_close_makes_the_ticket_record_so_the_commit_starts` uses a new `FakeExec.on_status` hook that derives `git status` from the fake tree, so the test proves the close lands before the record check.
- `test_the_close_waits_for_the_phase_gate` proves a work `.phase` still exits 2 with the ticket untouched.
- `test_close_is_refused_outside_a_commit` proves the refusal.
- Run: `python3 wispy/tests/test_wispy.py` → 97 tests, OK.

**Docs**
- The script docstring shows `wispy commit [--skills LIST] [--close] [flags]`, describes the flag in the commit paragraph, and lists it under Flags.
- `md/design/wispy.md` gains the flag in the command surface plus one paragraph on what the flag writes and how the subject follows.

**Ticket** (`.tickets/wisp-gkk6yp/ticket.md`)
- A `## Decision` section records C, names the rejected options, and states the test evidence.
- The frontmatter says `status: 'closed'`. Reopen the ticket with `wispy run` if you want another round.

## What this does not do

- The flag does not amend or rewrite an already landed commit, which is why A stayed rejected.
- The flag does not reopen a `closed` ticket, so a retry after a failed commit session keeps the closed status and proceeds.
- No commit was made; the changes sit uncommitted in the work tree.
