**Goal:** Diagnose why `wispy commit <<<"close then commit"` closes the ticket but commits a `wip(...)` subject.

**One sentence:** `wispy` renders the commit subject from the ticket status before the commit session runs, so a status change made during that same session cannot reach the message.

**Four sentences:** `cmd_commit` opens the ticket and freezes `wip(<id>): <name>` into the prompt. The steering block then tells the session to close the ticket and commit. `commit-rules.md` orders the session to use the subject given above. The session closes `ticket.md` and commits the frozen `wip(...)` subject; `cmd_commit` never re-reads the ticket afterwards.

**Diagnosis**

The bug is a stale value, not a broken close. `cmd_commit` reads the ticket once at `wispy/wispy:1067`. `commit_subject` (`wispy/wispy:538`) renders `<status>(<id>): <name>` from that read, and `commit_turn` (`wispy/wispy:610`) writes the result into the prompt as literal text:

```
Ticket id: ai-test
Ticket name: Test ticket
Ticket status: wip

The commit subject is
  wip(ai-test): Test ticket
<steering>
close the ticket, then commit
</steering>
```

The `<steering>` block follows the frozen header. The session edits `ticket.md` to `status: 'closed'` and then commits. `prompts/commit-rules.md` says "Use the subject given above," so the session obeys the stale line. Closing is model work under steering, not a wispy verb: `COMMANDS` holds only `run`, `continue`, `steer`, `commit`, `response`, and no source path writes `closed`. After the session, `cmd_commit` checks the exit code, that HEAD moved, and that the ticket dir is clean — it never re-reads the status or re-derives the subject.

**Evidence**

- Model-free reproduction: a dirty tree, stdin `close the ticket, then commit`, and an `on_stream` hook that rewrites the ticket to `closed`. The streamed prompt holds `Ticket status: wip` and `wip(ai-test): Test ticket`; `ticket.md` ends `closed`.
- Real instance: commit `93d864d` has subject `wip(ai-wpueub): wispies`, and its committed `.tickets/ai-wpueub/ticket.md` says `status: 'closed'`. Its body says "User steering closed the ticket."
- Working route: a close in an earlier session, then commit. Commit `44d5231` reads `closed(wisp-elak2h): ...` because the close landed before the prompt was built.

**Fix options (awaiting your decision)**

- **A:** re-read the ticket after the session; on a status change, rewrite the first message line via `git log -1 --format=%B` and `git commit --amend -F -`.
- **B:** fail after such a status change with a repair note, so the mismatch cannot land silently.
- **C:** add a `close` verb or a `--close` flag that sets the status before the prompt is built.
- **D:** order the session in `commit-rules.md` to re-derive the subject after any close; this leaves the outcome to the model.
