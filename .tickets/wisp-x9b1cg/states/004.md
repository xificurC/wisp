# Cache
- Wisp's steer burst path costs one turn: `steer_command` only appends a JSON line to `wisp.steer.inbox` with no liveness check and no wake; `steer_intake` renames the inbox, turns each line into one steered record, and flushes once; `run_agent_loop` drains once before the prompt; `loop_rounds` drains at the top of every round, so steers queued during one round share one request. Verified with the fake endpoint: 3 steers plus the prompt produced 1 POST, 3 steered records before the prompt, each rendered as "Steering message added m…". (From: `wisp/wisp` `steer_command` 840-861, `steer_intake` 873-925, `run_agent_loop` 802, `loop_rounds` 1240; `/tmp/steer_burst_check.sh`, `/tmp/steer_burst_check2.sh`) (Serves: Next)
- The design contradicts itself on coalescing: §1 says the hearth already merges the deliveries into one run, so the warden saves no run, while G2 lists coalescing as a cost bound and G26 says coalescing merges messages. Only `held` deliveries merge; the arithmetic batch width is one 250 ms tick, because `deliver()` then `admit()` starts a run on the first pending delivery. A hard delivery therefore costs one run per message when the burst spans ticks or lands after a run ended. (From: `design-options.md` §1, S4 delivery classes and the 515 line, S6 tick algorithm, G2 1165, G26 1189) (Serves: Open)
- The merge window proposal: a delivery is eligible for `admit()` when it is `EMBER_MERGE_WINDOW_MS` old, measured from the first pending delivery for that member; the class stays `held` while the window is open, then becomes `hard`; `--andon` skips the window; soft deliveries and TTL do not change. On the §1 example at 1500 ms, four wakes to `w1` become one run, and the later messages arrive while the run is live and ride soft. (From: derivation on `design-options.md` §1 example, S4 delivery classes, S6 tick algorithm) (Serves: task v0)
- R4 loses one message: the writer opens `wisp.steer.inbox`, the drain renames/reads/removes the inbox, the writer writes into an unlinked inode. A `flock` on `<sessiondir>/wisp.steer.lock` in the writer (open→write→close) and the drain (rename only) closes the race; a test harness drove the real functions, 50 runs, 0 losses, one loss without the lock.
