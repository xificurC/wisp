Goal: answer why W1 adds `--batch` to `wisp steer`, show what breaks without the flag, and decide whether the flag can go.

**TLDR:** The flag selects the input contract: prose versus one JSON object per line. Without `--batch`, a three-message delivery arrives as one message holding raw JSON, no per-message key, and no expiry. The flag can go, but the cost is breaking every prose caller, including `wispy steer`; keep the flag.

## The example

Ember delivers a digest line plus two bodies. That payload is three JSON lines. Piped to today's `wisp steer`, which reads stdin whole:

```bash
printf '%s\n' "$DIGEST" "$BODY1" "$BODY2" | wisp steer -d DIR
```

The inbox gets one line, not three:

```
{"content": "{\"content\":\"one\"}\n{\"content\":\"two\",\"key\":\"k2\"}\n{\"content\":\"three\",\"key\":\"k3\"}"}
```

I ran this against the fake endpoint with no paid call, next to a control where the same three lines entered the inbox as three lines. The model saw:

| Input | Request messages from the steer | Steered records in `wisp.jsonl` |
|---|---|---|
| three JSONL lines through `wisp steer` | 1, text = the whole escaped JSONL | 1 |
| three JSONL lines already in the inbox | 3, texts `one`, `two`, `three` | 3 |

## Three things break, not one

1. **Framing.** Without `--batch` the model reads transport syntax: `{"content":"two","key":"k2"}` is prose to the model, not a second addressed message.
2. **The ack.** The current intake keeps `content` and `wisp_steered` only (`records.append`, `wisp/wisp` 932). Keys disappear in both rows of the table above. Ember's only acknowledgment is `wisp_steer_key` in `wisp.jsonl`, so a collapsed batch never acknowledges. Every message escalates again at `reap()` (R2), forever.
3. **Expiry (Q22).** `expires_at` needs one line per message. One collapsed line has one place for one expiry.

The digest boundary is a fourth, smaller loss: the digest line and the bodies merge into one text block.

## Can the flag go?

Yes, three ways, and each costs something:

1. **Always JSONL, prose moves to `--text`.** That is the same flag with the other name. It also breaks callers that exist today: `wispy steer` pipes a person's ticket text into `wisp steer -d DIR` (`wispy/wispy` 508-511), and `md/design/steering.md` documents the hand form. A person's text can hold JSON or code, so every caller must escape bodies by hand.
2. **Auto-detect from the first byte.** A message that is itself a JSON object gets silently unwrapped, because the parser strips the envelope the sender meant to deliver. A prose line inside a batch gets rejected or merged. Silent misrouting on a delivery path is the one failure the design cannot accept.
3. **A second verb for batches.** Two names for one inbox, and the inbox format stays wisp's to own. A caller that writes the file directly, the hearth included, duplicates wisp's writer and must take wisp's steer lock, which is the race W1 closes.

Keep `--batch`. Ember is code, so the flag costs the hearth nothing. Prose stays the default because a human and `wispy` already rely on it.

One nuance: `--batch` alone does not fix the ack. Framing the lines is half of W1; the intake must also copy `key` to `wisp_steer_key` and honor `expires_at`. The two halves ship together.
