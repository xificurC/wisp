## What each request settled

**Injection and the steward.** The engine injects in exactly one place: a firing whose trigger atoms include `space.steer` does not start a run when a run of the rule's target type is live. The engine appends one line to that run's inbox with `wisp steer`, records the firing as `joined <run>`, and consumes the atom. A steward run may itself `wisp steer` any live worker, because a run is a model with bash and its words are data. Two writers now reach one inbox, so W1's `flock` (append plus intake) returns to the required set, lock only.

**Second steer while a steward is live.** `--join live` as a rule flag was designed, then dropped in favour of the flagless law above. The join needs no grammar change, no per-type slot, and no type special case. The join target is the earliest-started live run of the target type. A run in `starting` counts as live, so a burst cannot start a twin steward.

**Missing field.** Section 4.3.1 specifies one report for `no_result`, `no_output`, and `no_change`: field, type, run, rule, rule version, trigger atom with seq and source run, start and end times, exit, re-prompt count and time, result rows set, work dir, a 200-character excerpt of the last model words, and the fix command. The fault atom carries the machine fields. The re-prompt is one more `wisp run` in the same run dir under the same lock and wall clock, one turn per run covering every miss at once.

**`.done` on a decomposed run.** Every run carries an inferred parent: the lowest common ancestor of the runs named by the per-run trigger atoms. A rule on `me.done` therefore makes the splitting run the parent, so the sending agent is the parent with no flag. `agent-type:T.done` fires once per root run of T when the whole tree is green. `agent-type:T.failed` stays a per-run fault at any depth, because a repair cannot wait for a tree to settle. A green run that consumed a failed run's fault atom repairs that failure, so one repaired verification stops poisoning the root. A run started from a closure atom is a new root; without that law the tree would wait on a start that waits on the tree.

**Fork simplification.** New item W13 removes the cause of the rewrite. `<environment>` becomes a view rendered at request time from `wisp.run.json` and the `-d` path, never a record. `wisp.run.json` gains `created`, `sessions_root`, `project_dir`, and `env_in_system_prompt`; records carry no timestamp field today, so the creation time has no other source. `wisp fork` then copies `wisp.jsonl` and `wisp.run.json`, sets `created`, and touches no record. A legacy baked block is stripped and re-rendered, which is the only branch that reads the old format.

**`-F` everywhere.** Section 4.12 makes `-F FILE` and `-F -` the only body input for every `ember` verb. No verb reads bare stdin and no verb takes a body positionally. `result set` takes a JSON object through `-F` or a `FIELD=VALUE` scalar. argv carries only scalars and labels. A missing `-F` on a pipe is a `usage` error naming `-F -`. wisp's own verbs keep their stdin contract, because `wisp steer` has a documented human form.

**Syscall capture.** `strace -ff -y -s 0 -e trace=<curated>` wraps every engine-started run, so a source edit outside the work dir and a read of `~/.config` are recorded. Measured on this host with strace 6.8: one `python3 -c pass` costs 0.32 s and 0.66 MB with the curated set, against 0.51 s and 2.3 MB for `%file`; the floor is 9 ms per traced process; a trivial tool call traced 18 pids; `bash -c 'exit 75'` still reports 75 and a SIGTERM death reports 143. `unlink("gone")` carries no resolved path, so the parser tracks each pid's cwd from traced `chdir` and `getcwd`. Raw traces are deleted after the parse unless the run failed. The work dir stays for declared outputs, not for attribution.
