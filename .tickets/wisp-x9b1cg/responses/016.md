**TLDR.** Yes, move the switch to `wisp build-system-prompt`; the marker rides the system record and no text is composed twice. Planned work: nine `wisp` changes, a new `ember` daemon with one event log per space, and the rule language in `rule-language.md` §4.

## 1. W13: the switch moves to `build-system-prompt`

**Facts from `wisp/wisp` today.** `new_session` (line 236) calls `environment_block()` and prepends the result to the `-s` file's text; `write_initial_log` (2680) stores `{"type": "system", "content": ...}`. `build-system-prompt` (667) composes the wisp block, the AGENTS.md chain, the skills catalog, and stdin; the command takes no `-d` (line 65). Three request builders re-assemble system text: openai-chat through `message_of`'s fallthrough to `{"role": "system"}`, openai-responses through `instructions`, anthropic through `anthropic_system_text`. W13 needs one shared renderer for all three regardless of where the flag lives.

**Recommendation: yes, move it.** Four points.

1. `new` stops composing text. `build-system-prompt` becomes the only composer of a system prompt, which is the wart the owner names.
2. Name the output flag `--record`, with `--wisp-jsonl` as an alias if the owner wants the format word. The flag selects an encoding; it does not name a session, so the "no `-d`" rule holds.
3. Name the switch `--include-env`, not `--env`. At build time the command knows no session dir and no model, so `--env` cannot emit a block. `--include-env` emits `include_env: true` on the record and nothing else.
4. Give `-s` an explicit load rule: a file that parses as a JSON object with `"type": "system"` becomes the record verbatim; any other bytes become a text record as today. A hand-written persona that starts with `{` cannot misfire, because the rule also demands the `type` key.

**What the move buys.**

- The `-s`-without-env error path (1928) disappears.
- The marker travels with the record. `wisp fork` copies the marker, and no code re-derives system-prompt policy from `wisp.run.json`.
- `wispy/wispy:476` and the persona recipe (`wisp/wisp` 601) drop one flag and pass the record file.

**What the move costs.**

- `-s` accepts two encodings, and one test must pin the rule.
- `wisp.run.json` still stores `created` and `project_dir`, because records carry no timestamp and both values are cwd-dependent at render time. `sessions_root` derives from `-d`'s parent: `new` makes `<root>/<name>`, a fork under `<space>/runs/<rid>` reports `<space>/runs`.
- One renderer serves three builders. Render once, before the earliest record carrying the marker, and ignore later markers.

**What does not change.** The block is never stored. Every request renders the block from `wisp.run.json` and `-d`, so a fork reports its own dir and its own model. Rendering follows a model switch, where today's baked block freezes the creation model; the cache prefix changes only when the model changes, which invalidates the cache anyway.

## 2. The planned change set

**wisp: nine changes, built in this order.**

| # | Change | Effect |
|---|---|---|
| W13 | request-time `<environment>` | The block becomes a view; `fork` becomes a byte copy |
| W11 | `wisp new -d DIR` | A session under a named parent dir; missing parents are created |
| W7 | `wisp fork SRC -o DEST` | Copy `wisp.jsonl` + `wisp.run.json`, set `created`, rewrite no record |
| W2 | run lock | One live run per session dir; a typed busy exit |
| W4 | exit table + machine line | Guard 75, refusal 78, and the rest become readable facts |
| W5 | `status --json` | Committed records, model, guard state |
| W1 | steer lock, lock only | `flock` on the append and the intake; two writers exist now |
| W10 | `--no-stream` | An engine-started run writes no SSE |
| W12 | `--wallclock` | A run dies on a clock, for a stuck agent |

**ember: a new stdlib python3 program in `ember/` next to `wisp/`.** A daemon, the **hearth**, owns one SQLite WAL event log per space and a unix socket at mode 0700. Verbs: `space submit`, `rule add`, `result set`, `steer`, `query`, `why`, `trigger show`, `start`, `stop`. Every body enters only through `-F FILE` or `-F -`. The engine is arithmetic over rows and never waits for a model.

**Rule language: the parts that carry the work.**

- **Atom**: one immutable `category:value` fact, append-only. Fixed categories: `space` (`space.steer`, `space.settled`), `run:` (`run.started`, `run.failed`), `id:` (decomposition), `rule:<id>.capped`. Every other verb is a declared result field, so the field name is the verb.
- **Rule**: an event plus a typed edge, flags `--event`, `--require FIELD:TYPE[test]`, `--in`, `--out`, `--cap EXPR<N`, `--id`. A rule consumes the atom ids the rule binds, once per rule.
- **Agent type**: a wisp session dir made with `wisp new -d <space>/agent-types --name <type>`. A run is a `wisp fork` of that directory. No type file format exists.
- **Cell**: a named, versioned pointer to a work product. An absent declared output fails `no_output`; an unchanged output fails `no_change`; one re-prompt covers both, then `no_result`.
- **Tree**: every run has an inferred parent, the lowest common ancestor of the trigger runs. `agent-type:T.done` fires once per root when the whole tree is green; `agent-type:T.failed` fires per run at any depth; a green run answering a fault repairs the fault.
- **Steer**: the user's steer writes a `space.steer` atom, and a rule starts a steward run. A steer joins a live run of the rule's target instead of starting a second run. A steward may itself run `wisp steer` on a worker.
- **Admission**: cap 3 concurrent runs per space, two-phase start (run row and `run.started` in one transaction before the spawn), and a startup scan that fails a non-terminal run with a free lock as `crashed`.
- **Failure**: one named report per fault — field, type, run, rule, version, trigger atom, times, exit, re-prompt count, work dir, a 200-character tail, and the fix command.
- **Visibility**: `strace -ff -y` over a curated syscall set wraps every engine-started run and records reads, writes, deletes, and renames with resolved paths. The raw trace is deleted after the parse on success and kept for a failed run.
