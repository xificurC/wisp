**Dead-code deletion.** Removed from `ember/ember`: the `LEGACY_SOCK`/`LEGACY_PID`/`LEGACY_LOG` constants, the `retire_legacy` function, its call in `daemon start`, and the `path` parameter of `send_request` (the hook only the retirement used). `checks_rename` in `ember/tests/test_flow.py` lost its five retirement checks and gained one source check asserting `retire_legacy` is absent.

**N26 (a), landed.** `ember answer RID --dismiss`:
- Takes no `--field` and no `-F`; either alongside `--dismiss` exits 2 with `--dismiss takes no --field and no -F`.
- `command_answer` routes the dismissal through the daemon; `apply_answer` runs it after the existing manual-and-waiting checks, so a dismissal of a model run, of a done gate, or one carrying fields through the socket is refused with exit 2.
- The dismissal calls `finish_failed` with `reason=dismissed`, then pump, closure, and settle — the same tail the answer path takes. The fault atoms `run:RID.failed` and `agent-type:LABEL.failed` carry `value=dismissed`, so a rule selects the reason with `--event agent-type:LABEL.failed=dismissed`; the root's tree goes red and the space settles instead of hanging. A loop rule keyed on the verdict field does not fire, because a dismissal writes the fault verb, not the answer field.
- The manual briefing's closing instructions now name `--dismiss`.

**Tests.** `ember/tests/test_flow.py`: `checks_gate` covers the dismissal's unit arithmetic (refusals, failed state and reason, both fault atoms, re-dismiss refusal); `flow_gate` covers the CLI refusals plus an end-to-end dismissal — a resubmitted job's gate dismissed, no worker restart, `space.settled` carrying the new root in `red`.
