The goal of this turn: answer whether `ember daemon start` + `ember.sock`/`ember.pid` is coherent, and land the rename if so.

**TLDR:** Yes — one stem `ember.<kind>` for every state file, and `daemon` only as the process word; the rename is in the code, docs, and ticket, with 213 checks green three times.

**The naming answer**

- `daemon` names the process and only the process, so `daemon` appears in verbs and prose and in no file name.
- `ember` names the program and every file it writes: `ember.db`, `ember.sock`, `ember.pid`, `ember.log`, and SQLite's `ember.db-wal`/`ember.db-shm`. One stem, one rule.
- The stutter `~/.local/state/ember/ember.sock` is real and stays. `EMBER_STATE_ROOT` relocates the four files out of that directory, and out there the stem still says whose socket it is. A `daemon.*` stem would split one folder into two stems.
- Precedent: `/var/run/docker.sock` and `nginx.pid` name a program's state, not the program's role.
- No alias: `ember hearth start` exits 2 from argparse, so one thing keeps one name.

**Landed in `ember/ember`**

- Verb `daemon start|stop|status`, hidden `daemon _serve` for the spawn; `Hearth` → `Daemon`, `hearth_alive`/`call_hearth`/`command_hearth` → the `daemon_*` names; dead `require_hearth` dropped.
- `socket_path()`, `serve`, and `command_daemon` write and remove `ember.sock`, `ember.pid`, `ember.log`.
- New `retire_legacy(root)`, called by `daemon start`. A daemon built before the rename bound `<root>/hearth.sock` and writes the same `ember.db`. The charity case is corruption: two writers on one SQLite file. So `daemon start` sends that socket `shutdown`, waits up to 5 s for it to stop answering, removes `hearth.sock` and `hearth.pid`, carries `hearth.log` to `ember.log`, and fails with exit 1 naming the pid file when the old daemon will not stop.
- Smoke: temp root creates `ember.db`, `ember.log`, `ember.pid`, `ember.sock`; `daemon stop` leaves `ember.db` and `ember.log`; `daemon status` exits 1 when stopped.
