**Goal:** find pain in `ember` that an idiomatic change in `wisp` would remove, before `ember` v0 is built.

**One sentence:** `ember`'s de facto API is four private `wisp` files, so a small set of `wisp` commands and guarantees would delete most of `ember`'s file parsing, tail branching, and process reconciliation.

**Four sentences:** The four planned `wisp` patches make the steer inbox safe, but `ember` remains a second writer, a file parser, and a `/proc` reconciler. A single-writer steer command, a run lock, a resume verb, and typed errors remove the remaining races and the English-text scraping. An ack index, a status view, a supported model switch, and an in-place compact serve the long-lived member and retire the epoch noun. Roster, digest, governor, TTL, and spawn policy stay in `ember`; `wisp` should expose facts and mechanisms, not policy.

**Framing.** The build order already names four `wisp` changes: the steer lock, the drain order, the start-only drain, and the typed-key pass-through. Those four make the inbox safe. They leave `ember` writing `wisp.steer.inbox` directly (S0, S11 R4), reading `wisp.jsonl` for acks (§4.6), reading `wisp.run.json` for fallback (G12), and reading `wisp.log` for 429s (§9). The list below is the next layer.

## Tier 0 — races and duplicate logic, before v0

**1. The steer inbox has two writers.**
`ember` writes `wisp.steer.inbox` in `wisp`'s JSONL shape and takes `wisp`'s `flock` (S0, S11 R4). A batch must be one lock acquisition, so `ember` reimplements the append and the ordering.
Idiom: `wisp steer --batch` reads JSONL on stdin (`content`, `ember_id`, `ember_wake`), takes one lock, appends and commits in order; `--id KEY` handles one message; a busy lock is a typed exit.
Removes `ember`'s copy of the wire format and the lock protocol. R4 becomes a single-writer race, which is easier to close and test. The `cat wisp.steer.inbox` in §13.1 becomes a `wisp` command, not an `ember` output.

**2. No run lock, so "one live run per session dir" is a convention.**
G4 calls one live run a data-integrity law. `wisp` has no `fcntl` import and no lock on `run`/`continue`, so two runs share a commit point and corrupt `wisp.jsonl`. `ember` detects a hand-run by a stale pid row, records `run.lost`, and rebuilds slots from `/proc` plus process start time (R5, R7, G24).
Idiom: `flock` on `<dir>/wisp.run.lock` for the life of `run`/`continue`; write pid and start time into the lock file; exit 74 on busy; `wisp status` names the holder. This mirrors the hearth's own `hearth.lock` (R6).
Removes the `/proc` reconciliation, pid-reuse bugs, the `run.lost` guess, and the fork-then-transaction race (R5). The child holds the lock before `run.started` is a fact.

**3. `continue` versus `run` is a branch with a refusal.**
`ember` checks the tail, picks `continue`, and falls through to `run` when `continue` refuses a closed tail (S4 step 5, R3). A wrong guess costs a retry. `ember` must know `wisp`'s last-record rules.
Idiom: `wisp resume [-d DIR] [--prompt TEXT | --prompt-file FILE]`. Under the run lock, `resume` continues an open segment; on a closed tail, `resume` appends the prompt and runs. The wake prompt rides the same call.
Removes R3, the tail parser, the double-drain worry, and the "wrong guess" note in S4.

**4. Every failure is exit 1 and English.**
§9's retry ladder keys on 429, transport, degenerate stream, guard 75, and lock busy. Today `fail()` exits 1 for every error; an HTTP status lives in a stderr string and a `wisp.log` text line; `wisp` discards `Retry-After`.
Idiom: a small exit table (75 guard, 76 lock busy, 77 HTTP, 78 nothing to continue, 79 degenerate) plus one machine error line carrying `kind`, `status`, `retry_after`, and the body. `ember` classifies; `wisp` reports facts.
Removes stderr scraping, the fixed 1/5/25 s ladder guessing against the provider's own advice, and the ambiguity between "finished" and "broken".

## Tier 1 — the long-lived member, before v1

**5. There is no machine view of a session.**
`ember` reads `wisp.jsonl`, `wisp.run.json`, `wisp.usage`, `/proc`, and the inbox to answer five questions: is a run live, is the tail open, how many steers wait, which model runs, and what has been spent. `wisp ls` reports only model, record count, and mtime.
Idiom: `wisp status -d DIR --json`, with live/pid/start, tail kind, commit point, pending steer lines and keys, model/thinking, last error, and usage totals. Read-only like `ls`.
Removes four parsers and gives `ember ps` and the UI one source. Use `status` for observation only; decisions use the run lock and `resume`.

**6. The ack is an O(conversation) scan.**
§4.6 and §11.3 prove delivery by finding `ember_id` on a `wisp_steered` record in `wisp.jsonl`, so every tick parses a growing log and depends on `wisp`'s record shape.
Idiom: `wisp` appends a small `<dir>/wisp.steer.acks` index (`key`, record `seq`, ts) in the same commit as the steered record. The JSONL stays the truth; the index is a fast path and the seen-key set for the planned R8 dedupe.
Removes the scan, the record-shape coupling, and the dedupe scan.

**7. The fallback rewrites a private file.**
G12 and §9 rewrite `wisp.run.json` to switch models. `wisp continue` rejects `-m` (verified). The rewrite sits outside `wisp`'s API, and a torn write breaks `load_run_setup`.
Idiom: `wisp model set -d DIR -m M [-t T]` and `wisp model get`, one atomic writer, logged. The change also refreshes the `<environment>` block's `MODEL` line, which `wisp new` baked into the system record; otherwise a fallback leaves the persona naming the old model.
Removes private-format writes, the torn-file risk, and the stale persona claim.

**8. Distill needs a new epoch because `wisp` cannot compact.**
A guard 75 forces a new session dir, a new epoch noun, template re-application, a re-queue rule, and Q10's third hole (no event kind recovers `epoch`).
Idiom: `wisp compact -d DIR --summary FILE` under the run lock. Keep the system record, replace the conversation with one summary user record, keep the dir, usage, and identity. `_reload_committed` already rewrites `wisp.jsonl` when it drops a bad tail, so the mechanism exists.
Removes the epoch noun, template re-application, the epoch clause in the re-queue rule, and Q10's third hole.

**9. The digest is durable and taxes every later turn.**
§4 makes the digest a steered record. `steer_intake` appends every steered line to the conversation, and every later request sends all records. A 2–12 KB digest therefore repeats on every turn for the member's life, which undercuts S4's cost law.
Idiom: a steer line may carry `"ephemeral": true`. `wisp` injects the line into the next request and keeps it out of the durable conversation. Body lines stay durable because the ack needs them; the digest carries `ember_wake` and no `ember_id`, so the digest has no ack role.
Removes one growing digest per wake. Audit moves to `wisp.log` or `ember`'s event log. If the member needs the roster after the turn, `ember who` is one call, as S4 already says.

## Tier 2 — operations

**10. The child's stdout is the stream, and every fork needs a drain.**
`wisp` writes unbounded SSE, steer, and tool lines to stdout. A daemon that forks N children and uses a pipe must drain each pipe or block at 64 KB.
Idiom: `wisp run --stream FILE|off`. A file gives the UI a transcript; `off` keeps `wisp.log`. `wisp.stream` is already the child convention.
Removes one drain thread or pipe per member and the pipe-fill hang.

**11. `wisp new -d DIR` is parsed and silently ignored.**
Ember sets `WISP_SESSIONS_ROOT` per child and derives `session_dir`. Spawn templates are copied by hand and `wisp.run.json` rewritten (§7 spawn).
Idiom: honor `-d`, add `wisp new --from TEMPLATE`. Both are small.
Removes the root-env coupling, the manual copy and rewrite, and a silent footgun. I confirmed the ignore: `wisp new -d /tmp/x` created the session under the sessions root and exited 0.

**12. No run budget and no prompt file.**
`ember` arms a wall-clock timer, signals the child, and feeds the wake prompt through a pipe (§9 F5).
Idiom: `wisp run --wallclock S` exits 124 with a `wallclock` log line; `--prompt-file FILE` or `--prompt TEXT` carries the fixed wake line.
Removes `ember`'s timer and signal path, and the pipe-close hazard in a threaded hearth.

## What stays in ember

Roster, digest content, selectors, TTL, delivery classes, the merge window, slots, fairness, spawn policy, authority, and the UI stay in `ember`. `wisp` should not learn a queue, a scheduler, or a member model; S0 already rejects a daemon inside `wisp`.

Two Q10 holes have no `wisp` idiom: the owner reply route and the spawn grant. Those are `ember` addressing and policy. Only Q10's third hole moves, through finding 8.

## Priority and admission test

**Before v0:** 1, 2, 3, 4. Each closes a race or removes a duplicate implementation.
**Before v1:** 5, 6, 7, 8, 9. Each serves a member that lives for hours, not one turn.
**After v1:** 10, 11, 12.

The admission test for a `wisp` change: `wisp` already owns the file, format, or process, and the change removes a duplicate implementation or closes a race. Findings 1–9 pass. The governor, roster, and digest content fail, because `wisp` owns none of those.
