**1. "What happens when time or context runs out" — answered, documented, not changed.**
`ember` starts every run as `wisp run -d DIR --no-stream --wallclock $EMBER_WALLCLOCK` (default 600 s) and passes no `--context-guard`. A wallclock stop exits 124 and becomes `finish_failed(reason=wallclock)` before the contract check; a guard stop, if a caller armed one, exits 75 and becomes `reason=guard`. Both are terminal: no distill, no `wisp continue`, though the run dir stays resumable by hand. A context exhaustion without a guard arrives as an endpoint error (exit 77) and takes the one-re-prompt contract path. The written answer is `ember/README.md` §"Time and context today".

The space-level substitute is the `rescue`/`resume` pair: the failure atom starts a `distiller`, the distiller writes `handoff.md`, and `resume` starts a fresh worker as a child of the distiller.

## The recipe

A generic worker (no skills) picks up the job, a reviewer runs `ocr` and sets `approved:bool`, a no-go restarts the worker, three restarts capped, and a failure is distilled and continued. The target must be a git repo with one commit, and `ocr` must have a model configured.

```bash
export PATH="$PWD/wisp:$PWD/ember:$PATH"
export EMBER_SPACE=/tmp/pair
REPO=/path/to/repo            # named in the job file
MODEL=...                     # any model in wisp.modelcfg

# 1. Three system records, no --skills: the worker loads no skill.
cat > worker.persona <<'P'
You are a worker. The prompt is a job briefing.
Read every input path it lists. The task file names the target repo.
Work in the repo; keep the change minimal; run the repo's tests.
If an input names a review or a handoff, fix what it lists.
Write every declared output at the printed path in your work dir.
Set every required field with the printed `ember result set` command.
Do not commit.
P
cat > reviewer.persona <<'P'
You are a reviewer. The briefing lists task:prompt and the worker's answer.
Read the task file for the repo path and the acceptance criteria.
Run, from the repo:
  (cd "$REPO" && ocr review --audience agent -b "<the task>")
Redirect that group's stdout to review.md in your work dir.
Approve only when `ocr` reports no critical and no high findings.
If `ocr` itself fails, record the error and approve nothing.
Write review.md with the verdict, each finding, and the fix it needs.
Then run: ember result set approved=true|false
P
cat > distiller.persona <<'P'
You are a distiller. A worker run ended without finishing.
The trigger line names that run. `ember query run:<id>` prints dir,
workdir, reason, and the last words. `wisp render-past -d <dir> | tail
-n 200` prints the log tail.
Write handoff.md: what was done, what is left, the exact next command
for each step, the partial output paths, and the failure reason.
Then run: ember result set handoff=true
P

for t in worker reviewer distiller; do
  wisp build-system-prompt --wisp --record --include-env \
    < "$t.persona" > "$t.sys.json"
done

ember space init
for t in worker reviewer distiller; do
  wisp new -d "$EMBER_SPACE/agent-types" --name "$t" -m "$MODEL" \
    -s "$t.sys.json"
done
ember hearth start

# 2. Pickup, review, loop, rescue, resume.
ember rule add --id pickup --event space.submitted --run worker \
  --require ready:bool --in task:prompt --out answer:answer.md

ember rule add --id review --event agent-type:worker.ready --run reviewer \
  --require approved:bool --in task:prompt --in .out \
  --out review:review.md

ember rule add --id loop --event 'agent-type:reviewer.approved=false' \
  --run worker --require ready:bool --in task:prompt --in .out \
  --out answer:answer.md --cap 'agent-type:worker.ready<4'

ember rule add --id rescue --event agent-type:worker.failed \
  --run distiller --require handoff:bool --in task:prompt \
  --out handoff:handoff.md --cap 'agent-type:distiller.handoff<3'

ember rule add --id resume --event 'agent-type:distiller.handoff=true' \
  --run .parent --require ready:bool --in task:prompt --in .out \
  --out answer:answer.md --cap 'agent-type:worker.ready<4'

# 3. One job at a time; the job file names $REPO and the task.
ember space submit -F job.md
```

Read the space back with `ember query runs --tree`, `ember why`, and `ember query run:<rid> --files all`.

How the four worker runs arise: `pickup` starts worker run 1 and writes `agent-type:worker.ready` (count 1). `review` starts the reviewer. A no-go writes `agent-type:reviewer.approved` with value `false`, and `loop` fires while the ready count is below 4, so runs 2, 3, 4 happen. At the count of 4 the firing is blocked, `rule:loop.capped` is written once, and the space settles. `resume` shares the same cap expression, so exhaustion restarts and no-go restarts draw from one budget of three.

Three names to avoid and one shape to keep:

- Never name a required field `done`: `agent-type:T.done` is the closure verb, and `infer_parent` turns such a trigger into a new root. Use `ready`, `approved`, `handoff`.
- `resume` keeps `--run .parent`, so the resumed worker is a child of the distiller. As a sibling it would be invisible to `tree_ok` on the failed run, and the tree would never go green.
- `answer:answer.md` and `review:review.md` are versioned cells: each loop must change the bytes, or the run fails `no_change`.
- The cap is space-wide, so submit one job at a time.
