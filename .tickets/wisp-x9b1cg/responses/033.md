## The name question (N29, open, rec: keep)

A **space** is data: one registered directory holding rules, atoms, runs, cells, work dirs, agent types. A space is never started. `ember space init` registers the directory; `ember space pause`/`unpause` holds or releases its admission.

The **hearth** is the only process: one daemon per user at `EMBER_STATE_ROOT` that pumps atoms into rules, admits pending runs under the global cap of three, polls child exits, joins steers, and reconciles crashes. `ember hearth start` takes no space argument because one daemon tends every space.

So `ember space start` names the wrong thing twice: no space has a process, and no verb can start one space's process. If the round-2 metaphor must go, `ember daemon start` is the honest rename — a pure alias. The question is recorded as N29 in the Gaps table with four options; the recommendation is (a) keep, (b) rename acceptable.

## Design B, landed

Code in `ember/ember`, no `wisp/wisp` change:

- **`--run human:LABEL`**: a reserved `human:` prefix; LABEL is a pseudo-type with no `agent-types/` directory. `rule add` requires `-F` (the question) and refuses `--guard`, `--wallclock`, `--model`, `--thinking` on a `human:` target.
- **State `waiting`**: `NONTERMINAL` gains it, `LIVE_STATES` does not, so a gate blocks settlement and closure exactly as a live run does, holds no cap slot, and `admit` never picks it. The row has `mode manual`, empty `dir`/`workdir`, `started` at creation.
- **`ember answer RID --field F=V ... -F FILE`**: a mutating verb through the hearth. It type-checks every declared field through the shared `typed_value` (the same parser `ember result set` uses), stores the answer text on a new `answer` column, and calls the unmodified `finish_success`. Atoms are `agent-type:LABEL.FIELD` and `run:RID.done`, so a loop rule on the verdict is the existing reviewer loop with a human in the chair.
- **Guards**: `reconcile_space` skips the state `waiting` and `mode manual`, so a hearth restart leaves a dirless gate waiting; `answer_of_row` reads the stored text for manual rows, so the next briefing's `answer:` block carries the human's words; `ember result set` refuses a manual run; `ember why` lists `waiting:`; `ember query run:RID` prints a `question:` block.

Tests: `ember/tests/test_flow.py` grew `checks_gate` (waiting arithmetic, reconcile skip, manual answer reader) and `flow_gate` (gate opens, holds no slot, blocks settlement, survives a hearth restart, refuses bad bool / missing field / `result set` / re-answer; one rejection restarts the worker under the gate with the human's answer in its briefing; one approval settles green). **202 checks, three consecutive full runs after the last code change, no paid call.**
