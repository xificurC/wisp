**Goal.** Design a control plane that lets many `wisp` sessions form a space, exchange addressed messages, wake each other, share a concurrency cap, spawn helpers, and survive a crash of any party — and name the ball of wisps.

**One sentence.** The ball is an **ember**, and a deterministic python3 **hearth** process runs the bus while wisps remain the only place a model thinks.

**Four sentences.** A wisp is one small light, so a ball of wisps is an ember: one body of light that dies down and rekindles, which is the durability property the request asks for. The coordinator is a script because every mechanical decision is arithmetic over rows, and only judgment goes to a wisp, as an optional **warden**. Eleven seams carry the requirements: store, placement, membership, delivery, addressing, governor, spawn, observation, recovery, authority, packaging. The seams compose because three couplings are named and the rest stay independent, and one end-to-end trace exercises every seam once.

---

## 1. The name

**Ember.** The daemon that tends embers is the **hearth**, waking a wisp is **stoking**, and the urgent flag is **`--andon`** (the factory cord: pull it and someone must look now).

| | Name | Metaphor | CLI | Why not |
|---|---|---|---|---|
| 1 | **ember** | ball of light; rekindles from ash | `ember new lab` | — pick |
| 2 | fen | the marsh where wisps live | `fen new lab` | names the place, not the ball |
| 3 | lantern | the vessel holding many lights | `lantern new lab` | the vessel is the daemon, not the space |
| 4 | glow | "a glow of wisps" | `glow new lab` | loses the durability story |
| 5 | skein | many flyers moving as one | `skein new lab` | no light in the name |

Nouns stay plain: **member** (a wisp in an ember), **message**, **slot** (one live run), **job** (the sentence explaining why a member is here), **template** (the session a spawn copies), **digest** (the bounded text one wake receives), **epoch** (one session of a member, bumped by a distill), **marker** (`[ember:<id>]`, the string that proves delivery).

## 2. Script or wisp — the tradeoff, stated

| Criterion | Script | Wisp |
|---|---|---|
| latency per bus event | 1–5 ms | 1–10 s |
| cost of a chatty space | zero | the bus outspends the workers |
| slots and cursors | exact | not offered |
| restart | 20 ms from the store | the context *is* the state |
| testing | unit tests over a temp dir | statistical evaluation |
| audit | every decision is a row | every decision is prose |
| throughput ceiling | one process | one context window |
| "who should review this?" | cannot | can |

The wisp wins only the last row. So the split is by **kind of decision**, not by component: the script owns membership, sequencing, delivery, cursors, slots, retries, and spawning; a **warden** wisp reads the digest and writes a *proposal* event, and the hearth never blocks on the proposal. Law: **the bus runs at the speed of the filesystem, never the speed of a model.**

## 3. Shape

```
owner ─┐
wisp ──┼─ ember CLI ── unix socket ── HEARTH (python3, one per root)
       │                                  ├── SQLite WAL (only writer)
UI ────┘                                  └── spawns/reaps: wisp run | wisp continue
```

A wisp touches the bus through five verbs called from bash:

```shell
ember send @rev "lexer.py:88 looks off by one"   # DM
ember send @all --note "parser branch pushed"     # broadcast, wakes nobody
ember who                                          # roster with each job
ember spawn zero-trust --job "audit lex.py"       # dynamic spawn
ember left "done: 3 findings"                      # leave, with a reason
```

Nine invariants hold the design together. The load-bearing ones: the hearth is the only writer; a member holds at most one live run (two runs on one session dir corrupt `wisp.jsonl`); a slot is a live run; a wake costs a turn, while spawning, joining, and queueing cost nothing; delivery is proven by a marker in `wisp.jsonl`, never by an exit code; membership is a record, a process is a moment.

## 4. The seams, with the options each one weighed

| Seam | Options | Pick, and the losing argument |
|---|---|---|
| S0 packaging | standalone `ember` / subcommands in `wisp` / shell + jq | standalone: a daemon inside a one-shot runner degrades wisp |
| S1 store | flat files + flock / **SQLite WAL** / immutable files | SQLite: ack + cursor + slot must be one transaction; `ember dump` restores grep |
| S2 placement | **daemon + socket** / lockless CLI / per-space supervisor | daemon: with no resident process nobody fills a slot that frees |
| S3 membership | **record with job** / + lease / scan session dirs | record: leases evict live-but-idle members; a scan loses the *why* |
| S4 delivery | **digest by tail** / raw steers / polling | digest: closed tail → `wisp run` with the digest as prompt; open tail → `wisp steer` + `continue` |
| S5 addressing | flat ids / **selectors resolved at send** / topics | selectors: topics add a second namespace to observe |
| S6 governor | FIFO cap / **weighted fair share + aging** / per-ember caps | fair share: FIFO starves the second ember, the exact case the request names |
| S7 spawn | free / **policy-checked** / two-phase approval | policy: free spawn is a fork bomb; approval stays opt-in per ember |
| S8 observation | CLI text / **CLI + read-only SSE** / second server | SSE in the hearth: the DB is already safe to read concurrently |
| S9 recovery | **at-least-once + marker ack** / exactly-once / no retry | marker ack: exactly-once reimplements wisp's commit machinery |
| S10 authority | **socket path 0700** / + `SO_PEERCRED` / tokens | socket path: tokens add rotation for no gain on one host |

Three couplings are real and named: S4×S9 (the ack reads the marker), S4×S6 (a wake takes a slot), S2×S6 (no daemon, no admission). The remaining seams are independent, and a coverage table in the design maps every stated requirement to its seam.

## 5. Four facts I verified this round

Fake endpoint, no paid call:

| Claim | Result |
|---|---|
| a killed run leaves an open segment | yes, a `tool` tail |
| `wisp continue` resumes that segment | yes |
| rewriting `wisp.run.json` before `continue` switches the model | **yes — the request carried the new model** |
| `wisp continue` drains the steer inbox | yes, committed with `wisp_steered: true` before the loop |

The third row contradicts kodama's design note that a guard-stopped session cannot change its model pair. The setup is read at every run start, so a rate-limited member retries on a fallback model **without losing its context**. The fourth row is the whole delivery story: `steer_intake` commits before the round loop continues, so the marker is on disk before the model sees anything.

## 6. Gap analysis — the parts the request does not decide

Twenty gaps are decided in the document; five change the shape:

- **A wisp has no sleep.** "Wake a sleeping wisp" becomes "start a run for a member with no live run". The cost: a wake is a turn, and idle members are free.
- **Broadcast is a token amplifier.** Ten sleeping members receiving a broadcast cost ten runs. Hence coalescing (five messages → one digest), TTL, and `--note` (wakes nobody) versus `--now` (wakes the resolved set), with the wake count printed before the send commits.
- **The receiver's context is the scarce resource.** A long-lived member accumulates steered records, so a guard stop raises the limit once and then distills into a new epoch, keeping the member id and the job.
- **Ordering is per member only.** No global delivery order exists; replies carry `corr` and nothing else depends on sequence equality.
- **Rate limits are per model, not per ember.** Two limiters are needed: slots (live runs) and a token bucket per model shared by every ember.

## 7. Composition, in one trace

Six members in `lab`, four in `ops`, cap 3. The owner joins `w1` (free, no run). `w1` spawns `w4` with a job (free until a message). `w1` DMs `w4` with `--now` (slot 1/3, digest stamped `[ember:12a1]`). `w1` broadcasts a note (six delivery rows, zero wakes). `w2` and `w3` take slots 2 and 3; `w5` and `w6` queue. `w4` hits a 429, the hearth parks the model, rewrites the pair, and retries with `continue` — the message survives because no marker appeared. `w6` ends, a slot frees, and admission gives the slot to `ops`, which has surplus against its fair share. The hearth is killed `-9`, restarts, rebuilds projections, adopts two live children by pid, and requeues the rest. `w4` replies with `--re 12a1`; `w1` is idle, so the reply is a hard wake, and the digest is the prompt.

Every requirement appears once in that trace: namespace, soft and hard wake, cap with slots opening, DM, broadcast, join with a reason, dynamic spawn, durability, observability, recovery.

## 8. Build order

v0 addressing + durability (wake = hold) → v1 slots + hard wake + coalescing → v2 spawn + templates + policy → v3 recovery → v4 read-only UI with message-to-turn drill-down → v5 warden. The hearth takes wisp's own `Fs`/`Clock`/`Rng` seams plus `Runner` and `Bus`, so a NullRunner with scripted exits (`0`, `75`, `429`, `-9`) makes admission, fairness, coalescing, and recovery deterministic unit tests with no model and no processes.
