## Did we drop the global cap by accident?

Yes. Three facts from the code and the ticket:

- The ticket Goal (round 7) still says "share a concurrency cap", and Q2 settled "a constant **3**" as the global default.
- The implementation is per-space: `admit(limit=CAP_DEFAULT)` counts `live_runs(conn)` on one space's `ember.db` (`ember/ember` 1366), the socket is `<space>/hearth.sock`, and no cross-space state exists anywhere. Two hearths on two spaces run 6 concurrent wisp runs.
- No round decided a per-space cap. Round 12's build gate was "v0 is one space end to end", so the hearth came up per-space, and round 24's README line "there is no single global daemon" restated the implemented shape without a decision behind it.

## Is a single global daemon feasible?

Yes, without scope creep. Every hearth duty is per-store, not per-space: `Hearth.pump` fires rules on landed atoms, `admit` fills cap slots, `Hearth.poll` reads child exits, the steer join needs a watcher inside the 0.36 s spawn window, and the one-writer law serializes one store. One daemon can hold N stores.

The shape (N27 option a):

- One daemon, one socket at a fixed user path, plus a small space registry listing space directories; `ember space init` registers.
- A space stays a self-contained directory with its own `ember.db` — portable, archivable, no schema change. The daemon opens one connection per registered space and stays the only writer, so the one-writer law holds per store and overall.
- The CLI keeps `--space`/`EMBER_SPACE`; the space path rides the request payload. Read verbs keep opening `<space>/ember.db` read-only directly.
- The global cap is one live-run count across all open connections, with round-robin admission across spaces so one hungry space cannot starve another. Q2 and the Goal are restored.
- `reconcile` at daemon start iterates the registry.

Named costs:

- Blast radius: a daemon restart pauses pump and poll for every space. No work is lost — a spawned run carries no `PDEATHSIG`, so it survives orphaned, keeps its run lock, and `reconcile` re-adopts it.
- A per-space stop no longer exists as "kill its hearth"; it needs a pause flag, or the stop is global.
- `serve` currently runs `chmod(space, 0o700)`; that trick loses meaning, and authority moves wholly to the socket (S10 unchanged: 0700 now, SO_PEERCRED later).

The round-7 deferral holds: cross-space *coordination* — rules, atoms, cells, trees, steers crossing spaces — stays deferred. Only admission is global, which is exactly the Goal's shared cap and not the deferred bus.

The alternative (N27 option b) keeps per-space hearths and adds a crash-safe global slot ledger: one `flock` per slot, held for a run's lifetime, auto-released when a hearth dies. It works, but it adds a second mechanism and splits the live-count truth between the ledger and the run rows. Option (c) accepts per-space caps and amends the Goal. I recommend (a).
