**TLDR:** The four open questions settled, v3 landed in `ember/ember` (the three targets, the per-run result rows, `--guard`, `--wallclock`, `--model`, `--thinking`, the `--out` categories, the fault atom's reason), and the space recipe is now one generic worker plus an `ocr` reviewer running a capped loop, with a same-session distill behind it.

**Goal of this turn:** record N13, N14, N18, N19, implement what they imply, and hand back the updated recipe for a worker/reviewer loop.

## Settled

- **N13 — a wallclock stop is a failure, period.** `finish_run` tests exit 124 before the contract check, so a run that wrote every output still fails `wallclock`. The space-level rescue is the only continuation.
- **N14 — `session-file:` and `resource:` are the two `--out` categories.** `rule add` refuses any other. A `session-file:` output lands in the run's work dir; a `resource:` output lands in `<space>/resource/`, outside every work dir, and the cell store versions both.
- **N18 — `--model` and `--thinking` are rule flags**, passed to `wisp fork -m/-t`. They cover every target that forks a dir (`--run TYPE`, `--run .parent`, `--fork`). `--resume` forks nothing and refuses both.
- **N19 — the fault atom's value is the reason.** `run:<id>.failed` and `agent-type:T.failed` carry `value=reason`, so `--event agent-type:T.failed=guard` selects one reason and `--cap 'agent-type:T.failed=guard<3'` counts one reason.

## Landed

`ember/ember` holds the three targets (`.parent`, `.resume`, `.fork`), per-run result rows (`{"run": rid, ...}`), the four rule flags, `resource:` output paths, the fault atom's reason value, `mode`/`source` columns with an `ALTER TABLE` migration, `prepare_run_dir` returning `(error, reason)` so a live source fails `busy`, and `EmberExit` so a refused argument's text survives the hearth's reply (before, a bad `--event` or `--out` answered `error: 2`). `ember/tests/test_flow.py` grew `flow_guard`, `flow_resume`, and `flow_fork`: 102 checks, three consecutive green runs, no paid call. ## The recipe

Two agent types, five rules, one space. Target repo must be a git repo with one commit, and `ocr` needs a configured model.

```bash
export PATH="$PWD/wisp:$PWD/ember:$PATH"   # from the repository root
export EMBER_SPACE=/tmp/pair
WORK=/tmp/pair-setup; mkdir -p "$WORK"; cd "$WORK"
REPO=/path/to/repo
MODEL=...                              # any model in wisp.modelcfg
REVIEW_MODEL=${REVIEW_MODEL:-$MODEL}   # optional: reviewer on another model

cat > worker.persona <<'P'
You are a worker. The prompt is a job briefing.
Read every input path the briefing lists. The job names a target repo.
Work in that repo; keep the change minimal; run the repo's tests.
A review input is a list of findings: fix what it lists and say what
changed. Write every declared output at the printed path, then set
every required field with the printed `ember result set` command.
When the briefing itself says you are continuing a stopped run, that
instruction wins: write the handoff it asks for.
Do not commit.
P
cat > reviewer.persona <<'P'
You are a reviewer. The briefing lists task:prompt and the worker's answer.
Read the task for the repo path and the acceptance criteria.
Run the review from the repo, keeping ocr.out in your work dir:
  cd "$REPO" && ocr review --audience agent -b "<the task>" > ocr.out
Approve only when `ocr` reports no critical and no high finding.
Write the declared output at the printed path: the verdict, then each
finding with its severity and the fix it needs. If `ocr` itself failed,
write that instead and approve nothing.
Then run: ember result set approved=true|false
P
for t in worker reviewer; do
  wisp build-system-prompt --wisp --record --include-env \
    < "$t.persona" > "$t.sys.json"
done

ember space init
for t in worker reviewer; do
  wisp new -d "$EMBER_SPACE/agent-types" --name "$t" -m "$MODEL" \
    -s "$t.sys.json"
done
ember hearth start

cat > rescue.md <<'P'
You are continuing this same session, which stopped before it finished.
Do not work on the job. Work from the conversation above.
Write the declared output at the printed path:
  - what you completed, with the commands that prove it;
  - what is left, as numbered steps with the exact command for each;
  - every partial or declared output path you produced;
  - why this run stopped: the briefing's trigger line names the reason.
Then set the required field with the printed `ember result set` command.
P

ember rule add --id pickup --event space.submitted --run worker \
  --require ready:bool --in task:prompt --out session-file:answer.md \
  --guard 70% --wallclock 1800

ember rule add --id review --event agent-type:worker.ready --run reviewer \
  --require approved:bool --in task:prompt --in .out \
  --out resource:review-latest.md \
  --model "$REVIEW_MODEL" --wallclock 1800

ember rule add --id loop --event 'agent-type:reviewer.approved=false' \
  --run worker --require ready:bool --in task:prompt --in .out \
  --out session-file:answer.md --guard 70% --wallclock 1800 \
  --cap 'agent-type:worker.ready<4'

ember rule add --id rescue --event agent-type:worker.failed \
  --run .resume --require handoff:bool --in task:prompt \
  --out session-file:handoff.md \
  --cap 'agent-type:worker.handoff<3' -F rescue.md

ember rule add --id continue --event 'agent-type:worker.handoff=true' \
  --run .parent --require ready:bool \
  --in task:prompt --in session-file:handoff.md \
  --out session-file:answer.md --guard 70% --wallclock 1800 \
  --cap 'agent-type:worker.ready<4'

cat > job.md <<P
Repo: $REPO
Task: <what to build, in one paragraph>
Acceptance: <what makes the work done>
P
ember space submit -F job.md
```

The five rules:

| Rule | Trigger | Target | What it does |
|---|---|---|---|
| `pickup` | `space.submitted` | `worker` | starts the job; guards the worker at 70% so the distill turn has room |
| `review` | `agent-type:worker.ready` | `reviewer` | runs `ocr`; writes one stable review path, `resource:review-latest.md`; sets `approved` |
| `loop` | `agent-type:reviewer.approved=false` | `worker` | hands the review back as an input, capped at four worker runs in the space |
| `rescue` | `agent-type:worker.failed` | `.resume` | one more turn in the stopped run's own session and work dir; the rule body is the distill prompt; capped at three handoffs |
| `continue` | `agent-type:worker.handoff=true` | `.parent` | a fresh worker run under the distill run, seeded with `session-file:handoff.md` |

Why the shapes are these:

- `--resume` keeps the session and the work dir, so the distill turn reads the work conversation and the job's files. It carries no `--guard`: a guard-stopped session sits at its limit, so a guarded resume would stop at its first round.
- The continuation is a separate `--run .parent` row, not a second run inside `rescue`, because one rule starts one run.
- Every failure reason enters `rescue`, including `guard` and `wallclock`. For a reason-specific branch, use `--event agent-type:worker.failed=guard` and a second rule.
- For the frozen variant, swap the rescue target to `--run .fork --model MODEL2`. The branch gets a copy of the session and of the work dir, and `--model`/`--thinking` switch its pair.

## What bounds the space

- Four worker runs at most: `--cap 'agent-type:worker.ready<4'` counts `agent-type:worker.ready` atoms space-wide, and `loop` and `continue` share the expression. Submit one job at a time.
- Three distill turns at most: each rescue firing writes one `agent-type:worker.handoff` atom, so `--cap 'agent-type:worker.handoff<3'` stops the rule. Without the cap, a failed resume retriggers its own rule forever.
- A settled space is green even after a fourth no-go. `.done` means the root's tree finished, not that the reviewer approved; read the `agent-type:reviewer.approved` atoms and `resource:review-latest.md` for the verdict.
- A green continuation heals the tree: the resume run is a child of the failed run and answers its fault atom, so a stopped job that the continuation finishes settles with an empty `red`.
- Never name a required field `done`: `agent-type:T.done` is the closure verb and `infer_parent` turns such a trigger into a new root. Use `ready`, `approved`, `handoff`.

Read a run with `ember query runs --tree`, `ember why`, `ember query run:<rid> --files all`. The reviewer's latest answer is always `$EMBER_SPACE/resource/review-latest.md`, and the cell store keeps every version.
