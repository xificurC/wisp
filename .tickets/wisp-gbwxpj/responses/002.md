Goal: run a second design round for kodama with the owner's review applied.

**One-sentence summary.** `design-options-2.md` defines one board, ten wake rules, agent templates copied per run, lane-scoped questions with peer answers, and a distill turn on guard 75; the ticket records the decisions and five open questions.

**Four-sentence summary.** The substrate is one `kodama-sessions/` root: agent templates under `agents/`, immutable JSON posts under `board/`, and tasks with artifacts, locks, and one run copy per spawn. A spawn copies a template, rewrites `wisp.run.json` with the live-probe model pair, and runs one wisp session; a file-level test with no model call confirmed the persona survives and the rewritten model is honored. A question is a post with a `blocks` list, so one lane waits while the other lanes run; `--unattended` lets a peer answer bind, and two disagreeing peers escalate to the owner. A guard stop runs one unguarded distill turn, closes the session, and starts the next run from the handoff post; `task trace --all` plus the ledger index replaces the single `render-past`.

## What the review changed

- No `agent.toml`, no `needs`/`gives`, no `writes`. An agent is a wisp session template. `kodama agent submit` builds the persona and calls `wisp new`.
- The root is `kodama-sessions/`, not `.kodama/`.
- One lock per `(task, agent)`. Two workers on one task are excluded; a worker and an auditor run together.
- The model and thinking pair is a spawn decision, not a template constant. The router ports `__wisp_route`: deepseek V4.1 Flash at xhigh when free, else GLM 5.3 at high.
- A question blocks the paths in its `blocks` list, not the task. The task enters `asking` only when no other lane can proceed.
- A guard stop distills. It never continues the drained session.
- The ledger indexes every run path. `task trace --all` renders the merged view; `--run` and `--grep` target one session.

## Ten wake rules

A wake rule is one `pick(candidates, board, ledger)` function. The substrate stays the same.

| Rule | Next `(task, agent)` picked by |
|---|---|
| bulletin (default) | idle-weighted random |
| ranked | votes on open threads |
| auction | best bid on an open thread |
| bounty | best bounty over estimate |
| relay | the last post's `next:` hint, at probability p |
| stigmergy | decaying thread score |
| gossip | a random sample of posts |
| clonal | agent weights from citations |
| chorus | N parallel clones on a flagged decision |
| queue | the oldest unclaimed thread |

The old five survive: conveyor becomes queue, handoff becomes relay, epochs becomes chorus, stigmergy becomes field, blackboard splits into bulletin and ranked. Auction, bounty, gossip, and clonal are new.

## Open questions

The ticket's `## Gaps` holds five rows. My recommendations:

1. `accept` optional; fall back to a quorum of two agents plus one audit.
2. Default strategy: bulletin.
3. Peer answer: advisory by default; binding under `--unattended`.
4. Board: one root board with tasks as threads.
5. Merged trace: on demand, not stored.
