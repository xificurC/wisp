**Goal:** give tool-call code fences a language info string, so `bash` and `python3` commands are easy to find in a `render-live`/`render-past` render.

**TLDR:** The call fence now opens as ```` ```bash ```` or ```` ```python3 ````; every other tool keeps the plain fence. Both the streamed and the replayed path draw the same tagged fence, and tests pin it.

Code changes in `/home/pnagyux/code/wisp/wisp/wisp`:

- New `fence_of(name)` next to `display_key_of`: returns "```bash\n" for bash, "```python3\n" for python3, "```\n" for any other name. `load_image` draws a path and an unknown tool draws raw arguments, so a language tag there would mislead. The closing fence stays plain.
- `Renderer.tool_delta` opens the fence at the first fragment that carries the tool name, not at the first fragment, because the fence needs the name. Each call dict gained an `opened` flag. A wire that sends arguments before the name buffers them in `raw` and draws them when the name lands.
- `Renderer._close_call` writes a closing fence only when `opened` is set.
- `Renderer.tool_header` discards an unopened parked call and draws the whole block from the inject payload with `fence_of(name)`, so a call that never learns its name still renders correctly and identically on replay.
- The `render-live` help entry and the module docstring now say the fence is tagged with the tool name.
